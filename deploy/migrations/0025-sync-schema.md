# 同步相关表规范整改

适用 MySQL 8.4，从 0024_organization_schema 升至 0025_sync_schema。

- 数据集版本及同步计数、租约世代改为无符号整数，保留原值及空值。
- 数据集、待核实事实、任务明细、设置和租约补数据库维护的时间列。存量新增时间以迁移 UTC 时刻为起点。待核实事实的 updated_at 仍表示最近一次核实。
- sync_job 的 created_at、updated_at 原值重命名为 create_time、update_time，数据库自动维护后者，任务创建入口继续记录受理时的 UTC 时间，其他插入使用数据库默认时间。同步任务 HTTP API、管理端和初始化状态使用新名称。
- system_setting.key 改为 setting_key，保留原主键及设置值。
- 同范围活动任务使用生成列唯一约束，普通历史任务可以重复出现。全量任务的 NULL 根与显式根区分。覆盖验收遇到同范围活动任务时拒绝并在结束后重新发起，避免旧采集被误认为新验收。
- sync_staging 按任务生命周期清理，复合主键及原外键保留，适用暂存表省略时间列的例外。所有目标表既有外键、主键策略按历史规范保留。

## 执行与验证

1. 核对目标库版本、字符集、排序规则、迁移版本、字段及约束。检查负数计数和同范围重复活动任务。重复记录须核对业务归属后处理，迁移在有异常时拒绝执行。
2. 按发布流程停止写入者并验证备份可恢复性，在独立数据库演练升级和降级。同步更新应用、前端及调用方。
3. 用 schema_check 核验结构及应用会话；检查行数、历史时间、设置键、数据库自动维护时间和同范围去重。使用 EXPLAIN 核对任务列表、状态筛选和领取。
4. 失败时保持停写。逐表 DDL 原子提交，在线重试跳过已完成的表。降级前核对无符号计数没有超出有符号上限，保存新增时间以便恢复。数据异常使用迁移前验证过的备份恢复。
