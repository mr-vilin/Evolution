## Problem Statement

管理员希望在“组织服务”中获得 Ant Design Pro 完整模板的工作台体验，并在系统内参考完整示例页面。现有工程已采用 Pro 工程约定，但只保留业务所需的布局和页面，未包含完整演示案例；业务页面也需要在同一套导航、标题和内容层次下统一布局。

同时，管理员需要清楚区分真实组织业务与演示功能：真实组织、门店、同步、日志和管理配置继续使用飞书认证及既有接口，案例只能操作明确标识的演示数据。改版不能使已有业务地址、权限校验、冲突处理或独立初始化流程失效。

## Solution

在既定技术栈中补齐完整工作台外壳，使用“业务管理”“系统管理”“参考案例”三个导航区域，组织架构作为默认首页。沿用中文、“组织服务”品牌、官方默认浅色蓝主题、混合导航、可折叠侧栏、面包屑和布局设置抽屉，统一七类业务页面的布局。

新增仅管理员可访问的“参考案例”，按官方模板类别提供可交互的完整示例。案例在本地、测试和正式构建中保留，登录、注册、个人设置、表单、列表和聊天等交互均为本地演示；真实业务继续复用既有认证和接口。

以上总体方向属于已确认的 Q1–Q6。下文标为“Q7 候选”的版式、完整页面清单、交互细节和验收矩阵来自输入文档的最终实施基线草案，发布规格时仍须如实记录其确认状态。

## Implementation Decisions

### 已确认范围与现有约束

1. **总体范围（Q1–Q3）**：完整模板包含工作台外壳及完整示例菜单和页面；参考案例独立、可交互、仅管理员可见，并保留在全部环境构建中。组织、门店、同步、日志、设置、系统信息和人员详情一起调整布局。字段含义、业务操作、权限及初始化流程沿用现有规则。
2. **导航与视觉方向（Q4–Q5）**：采用业务管理、系统管理、参考案例三个区域，组织架构为首页；官方默认浅色蓝主题、混合导航、可折叠侧栏、面包屑、布局设置抽屉及中文品牌“组织服务”。
3. **案例行为（Q6）**：登录、注册、个人设置、聊天等使用本地演示；表单返回演示结果，列表模拟增删改，聊天模拟回复。真实业务沿用飞书认证和既有接口。
4. **模块边界**：调整工作台外壳与导航、公共页面容器、七类业务页面和共享响应式样式；新增参考案例页面及案例本地数据适配模块。复用现有中文 Provider、认证门禁、资源读取、表格、门店编辑与错误恢复能力，不替换整套前端。
5. **技术基线**：沿用 Ant Design Pro 6.0.3 的固定官方快照、Umi Max 4.7.23、Utoopack、Ant Design 6.6.4、ProComponents 3.1.14-2 和现有 React / TypeScript 版本。Pro 工程、组件库及产品版本分别管理。新增案例必需依赖时同步锁文件并验证严格 peer 兼容，不借机升级框架或构建工具；使用组件前按项目要求核对实际版本官方 API。
6. **认证和初始化**：真实登录仍由飞书认证、后端管理员白名单及统一 AuthGate 处理，保留会话和 CSRF 校验。系统没有现成的普通用户角色，本规格不新增该角色。初始化未完成时仍只呈现独立全屏向导，不提前挂载工作台或案例；保留步骤、字段、校验、失败重来及人工发起动作的既有边界。
7. **业务契约**：沿用既有接口、字段、筛选语义、分页和错误反馈。保留 `dataset_epoch` 与 `data_version` 的一致性、409 后整组重读与有限重试、门店预览后确认及草稿保护、任务详情的地址状态和轮询。业务数据版本不作为软件版本显示。
8. **配置交互**：面向用户的配置使用中文标签和结构化字段，多条目配置支持逐行增删改及字段级校验。JSON 由内部转换；日志中既有只读 JSON 展示可以保留，不增加 JSON 配置入口。管理设置的飞书连接项保留现有能力，不据“重新布局”推导出新的凭据编辑功能。
9. **数据与部署边界**：不新增数据库表、迁移或后端 API，不改变同源合并部署拓扑。实现验收阶段按既有标准工具发布本地 Docker；保留业务数据、会话、配置及 MySQL，不自动初始化、清理或触发同步。远端测试和正式环境发布需当次明确授权。
10. **既有工作保护与版本治理**：当前分支包含其他初始化、样式和文档修改；实施前逐项核对差异，重叠处逐段合并，不覆盖或回退既有工作。遵循既有 SemVer 与版本台账 ADR，日常开发记录 Unreleased，不因本规格或普通 PR 自动提升产品版本。

### Q7 候选：全局外壳与页面布局

以下内容等待最终基线确认；不能仅因其写入 Issue 就视为已经确认或实现。

- 默认流式内容宽度，保留固定顶栏和侧栏能力；侧栏随当前顶层区域展示页面，案例内部保留官方类别层次。
- 既有业务路径保持有效，人员详情在组织架构下选中；保留未知业务地址的现有兜底行为。案例 404 使用独立演示入口，不替代全站兜底。
- 使用统一页面头、面包屑、说明、主操作区、卡片和间距，不叠加重复标题或面包屑。
- 顶栏保留真实身份与退出，增加布局设置以及指向系统信息、官方参考的帮助入口；通知、搜索和个人资料等演示能力放入参考案例。
- 布局设置仅调整当前浏览器外观与布局，可恢复默认，不修改业务配置、其他管理员设置或权限；文案保持中文。

| 页面 | 目标版式 | 必须保持的行为 |
| --- | --- | --- |
| 组织架构 | 页面头；左部门树卡片、右人员列表卡片；集中筛选与工具栏；窄屏部门抽屉 | 选择与勾选独立，直属/含后代切换，批量门店设置，更新部门，人员详情 |
| 门店管理 | 筛选区、列表、行操作、员工抽屉和结构化编辑表单 | 全部/主门店归属，编辑前预览，确认提交，冲突保留草稿并重新预览 |
| 同步中心 | 状态卡片、连接摘要、任务和事件列表、详情抽屉 | 真实状态与筛选，全量更新，失败重试，详情深链接、轮询、终态刷新及前进后退 |
| 变更日志 | 筛选表单、列表、详情抽屉 | 查询/重置，原有筛选语义与时间转换，修改前后只读展示 |
| 管理设置 | 页面头与标签页或分组卡片，结构化表单 | 现有连接信息、白名单、只读客户端、每日核对；密钥展示及危险操作确认 |
| 系统信息 | 版本摘要、分组说明卡片、演进时间线 | 构建不一致与读取失败提示，实际架构和技术栈，现有文档入口 |
| 人员详情 | 页面头，基本资料、解析状态、部门关系、全部门店归属分组 | 全部原字段，唯一主门店解释，返回组织架构 |

### Q7 候选：完整参考案例与隔离方式

案例路由统一放入 `/examples/` 路径空间，并经过现有管理员与初始化门禁。下表共 27 个页面，均需有实际内容和有参考价值的交互，不以空白页、链接集合或单一通用占位页替代。

| 类别 | 页面 | 最低交互与内容要求 |
| --- | --- | --- |
| 欢迎与管理 | 欢迎页、管理示例 | 各自保留对应官方页面结构与参考内容 |
| Dashboard | 分析页、监控页、工作台 | 使用本地样本呈现各自图表和工作台结构 |
| 表单 | 基础表单、分步表单、高级表单 | 字段校验、提交反馈、分步状态及演示结果 |
| 列表 | 查询表格、标准列表、卡片列表、搜索文章、搜索项目、搜索应用 | 各类页面的查询、分页和对应模拟操作 |
| 详情 | 基础详情、高级详情 | 对应信息层次与本地样本详情 |
| 结果 | 成功页、失败页 | 对应结果反馈及页面提供的演示操作 |
| 异常 | 403、404、500 | 可访问的独立异常演示入口与反馈 |
| 账户 | 个人中心、个人设置 | 本地演示资料和设置交互 |
| 用户页面 | 登录、注册、注册结果 | 已认证管理员内的模拟流程，不生成真实账户或业务会话 |
| 聊天 | 聊天界面 | 输入、模拟回复及会话状态；不调用外部模型 |

- 每个页面明确标注“参考案例 / 演示数据”，样本不取自真实组织资料。演示增删改仅作用于当前案例会话，刷新恢复初始样本；不要求新增案例持久化机制。
- 使用案例专属本地适配层，不在生产应用注册拦截真实业务请求的全局假接口，不引入官方模板的第二套 currentUser/login 身份机制。
- 演示登录不创建或替换真实会话，演示注册不创建账户，个人设置不更改真实管理员资料；案例不触发真实同步、客户端或白名单管理写入。
- 案例不接入官方生产示例 API，聊天文本不发送到外部模型。帮助入口可跳转官方参考网页，区别于演示交互向外部 API 提交数据。
- 案例按路由加载，业务首页不提前加载全部案例；按官方源码实际需要补充图表或样式依赖，并保留源码出处及必要许可。

## Testing Decisions

### 已确认的测试边界

**主要入口采用应用级浏览器验收**：运行真实 Umi 生产构建及既有同源静态服务，通过页面、地址栏、键盘和可观察的网络请求检查结果。会话和业务响应在测试环境的 HTTP 边界注入合成夹具，参考案例运行实际本地适配层；不在生产代码内增加测试后门或全局假接口。

该入口可同时验证真实导航、统一外壳、异步资源、门禁、七类业务页以及 27 个案例。优先复用此前 Pro 迁移验收采用的构建页面加合成数据浏览器方式。仓库已有 Vitest / Testing Library 页面与组件回归，但未发现正式纳管的浏览器 E2E 套件；历史验收记录不能当作本次已存在且已通过的自动化。如需补齐自动化，只在这一应用入口建立可复用测试夹具，不为每个内部 hook 或案例组件另建测试边界。

继续运行并按受影响行为扩展现有 Vitest / Testing Library 测试：使用已有资源请求边界与导航适配，不新增一套业务模拟服务。此类测试用于快速定位回归，不能代替真实 Umi 构建的路由、样式或资源验收。

### 测试质量与既有先例

- 断言用户看到的中文信息、交互结果、地址变化、请求契约及数据隔离。避免断言内部状态形状、私有函数、组件树、样式类名或组件调用次数；无需为静态配置逐行编写镜像测试。
- 管理员门禁已有未登录和后端不可用回归，初始化页面已有全屏阻断及完成后进入系统测试；沿用这些入口补齐案例访问状态。
- 组织页面已有版本冲突后的父子整组重读、树搜索和批量草稿保护回归；门店编辑已有预览后提交、409 保留草稿和新版本重新预览回归。
- 同步页面已有任务深链接、轮询终态刷新和关闭抽屉时清理地址参数回归；错误边界已有查询参数变化保留筛选状态测试。
- 日志页面已有查询、重置和 UTC 参数转换测试；系统信息已有版本不一致和读取失败反馈测试。共享表格已有业务空值文案回归。
- 同源静态服务已有 SPA 深链接、异步 JS/CSS 的 MIME、未知 API 与缺失资源返回 404 的测试，可作为案例深链接和生产资源检查的先例。

### Q7 候选验收矩阵

| 范围 | 可观察的通过条件 |
| --- | --- |
| 导航与地址 | 三个区域可达、首页为组织架构；既有业务地址直接进入及刷新有效；人员详情选中组织区域；无重复标题/面包屑；未知地址沿用兜底 |
| 顶栏与布局设置 | 管理员身份、退出和帮助入口有效；当前浏览器设置可调整及恢复，重新打开业务页与初始化页无样式回归，不改变业务配置或权限 |
| 认证与初始化 | 401 仅显示真实飞书登录入口；403 不显示受保护内容；会话读取失败不误入系统；初始化未完成只显示向导；正常管理员可访问业务与案例，演示登录也不能绕过门禁 |
| 业务回归 | 七类页面保留既有字段、筛选、版本一致性、预览确认、冲突草稿、任务深链接及轮询、密钥和危险操作确认；只读日志详情不变成配置入口 |
| 案例完整性 | 按 27 页清单逐项核验可访问、结构、演示标识及异步资源；关键表单、步骤、列表操作、结果跳转和聊天可操作，不以菜单数量代替页面验收 |
| 演示隔离 | 实际操作案例并观察请求；除既有门禁或正常工作台所需读取外，不因演示动作调用真实写入口、官方示例 API 或外部模型；操作后真实会话与业务夹具保持原值，刷新恢复案例样本 |
| 按需加载 | 组织首页加载时不请求全部案例页面资源；进入案例后所需异步 JS/CSS 加载成功且 MIME 正确，资源失败有可理解的反馈 |
| 多端与可访问性 | 1440、1024、390 像素宽度分别检查导航、内容、表单、抽屉及表格；主要导航和操作可用键盘；窄屏宽表在内容区横向滚动，不造成页面整体溢出 |
| 视觉核验 | 以固定官方源码范围和确认后的布局为依据，实际查看参考页面与当前构建并保留检查证据；未完成参考站视觉检查时不宣称视觉一致 |
| 工程验证 | 类型检查、相关现有前端回归、生产构建、受影响 Ant Design 组件检查和产品版本校验通过；依赖变化时核验锁文件及严格 peer 兼容 |
| 本地发布 | 通过标准发布入口核验本地目标、任务状态和迁移版本，保存镜像与回退点；发布后检查镜像、页面、深链接及异步静态资源，再进行浏览器验收 |

实现时需运行前端 `npm.cmd run typecheck`、`npm.cmd test`、`npm.cmd run build`，以及仓库根目录 `node scripts/versioning.mjs check`。Ant Design 检查按项目技能与实际依赖版本执行。涉及静态服务变动时再运行相应既有后端测试，不为纯界面改版扩大数据库测试范围。

合成响应验收证明界面与请求行为，不证明真实飞书或业务数据库联调已完成。真实环境的写入验收仅在已有或另行获得的明确授权范围内执行；未执行项如实标为未验证。健康检查不能代替浏览器业务验收。

## Out of Scope

- 新增普通用户角色、改变管理员白名单或真实飞书登录机制，以及关闭 state、CSRF 或会话校验。
- 将演示登录、注册、个人资料、通知、搜索或聊天升级为真实业务服务，接入外部模型或官方生产演示 API。
- 修改组织、人员、门店、同步和初始化的业务规则；新增业务字段、接口、数据库结构或迁移。
- 通过此次改版执行初始化、清理业务数据、发起真实同步或进行客户端管理等业务写入。
- 框架升级、构建工具替换、部署拓扑拆分，以及引入 Redis、消息队列等新基础设施。
- 新增 JSON 配置编辑模式、将案例操作持久化到真实数据库、增加另一套身份机制。
- 自动发布测试或正式环境、提升产品版本、创建发行标签，或把构建通过描述为已经上线。
