## 1. 目标与依据

统一列表表格的容器高度、滚动方式、工具栏位置、列布局、内容表达以及筛选和排序交互。规范页通过中文规则和可操作的本地示例说明标准，供后续页面设计、开发和验收使用。

依据用户提供的表格示意图、业务列表截图及本次补充要求，沿用项目现有 React、TypeScript、Ant Design Pro v6、Umi Max 和 Ant Design 6.6.4，不引入新的表格组件库。

本方案采用以下筛选与排序约定：

1. 无新增类表格左上角最多展示 4 个主要筛选条件；超过部分使用对应列的表头筛选。
2. 数字字段支持按真实数值排序。
3. 筛选与排序统一使用 `filteredValue`、`sortOrder` 受控管理。
4. 同一时刻最多一列排序生效，所有列显式指定稳定且唯一的 `column.key`。

筛选条件数量按独立业务字段计算，不按一个下拉框内的选项数量计算。列头筛选使用 Table 的 `filters` 等列配置；`rowSelection.selections` 保留其行勾选用途。本方案不设置汇集额外条件的独立“更多筛选”入口。

## 3. 容器高度与滚动

### 3.1 高度计算口径

表格白底容器包括可选列表标题、工具栏、表头、表体、横向滚动条及分页区。

- `V`：浏览器或演示工作区的可见高度。
- `T`：固定顶栏等持续占用的顶部高度。
- `Gt`、`Gb`：顶部和底部必要留白，读取项目实际布局。
- `H = V - T - Gt - Gb`：页面可供完整表格使用的一屏高度。
- `Y`：表格白底容器在初始布局中的顶部位置，与视口使用同一坐标系。
- `A = V - Gb - Y`：首屏实际可分配给该表格的高度。

60% 的判断为 `A / H`，以整块白底容器可获得的空间计算，不以当前记录数量或实际表体高度计算。少量记录不应触发吸顶例外模式。

### 3.2 默认模式：首屏容纳

当 `A >= 0.6 × H` 时采用默认模式：

1. 白底容器最大高度为 `A`，底部不超过当前可见页面的底部留白边界。
2. 工具栏、表头和分页保持可见；超出高度的数据行在表体内部纵向滚动。
3. 表体可用高度为容器高度扣除标题、工具栏、表头、分页、边框及横向滚动条后的剩余空间。
4. 列宽超出时，在表格内部横向滚动，页面本身不产生横向滚动。
5. 记录较少时允许容器自然收缩，不为填满屏幕增加空记录或无意义空白。

### 3.3 例外模式：页面先滚动，表格再吸顶

当不可省略的上方内容使 `A < 0.6 × H` 时采用例外模式：

1. 表格按 `H` 的容量布局，允许其初始位置超出首屏底部，由页面承载到达表格位置所需的滚动。
2. 页面向下滚动，白底容器顶部到达固定顶栏下方的顶部留白边界后，整体吸顶。
3. 吸顶容器占满可用一屏；工具栏、表头、分页处于可见范围，表体按剩余高度内部滚动。
4. 吸顶及退出时保留布局占位，避免上下内容突然跳动。
5. 表体滚到边界后，用户仍能返回上方内容或继续离开表格；鼠标、触控和键盘均可完成操作，不永久锁定整个页面。

吸顶对象是包含工具栏、表头、表体和分页的完整白底容器。Table 的表头吸顶能力可作为内部配合，整块容器的高度和吸顶行为需要另行管理。

### 3.4 自适应与测量

- 窗口尺寸、缩放、顶栏、侧栏、工具栏换行及上方内容尺寸变化后重新测量。
- 模式判断依据初始布局或尺寸变化后的空间，不随每一帧页面滚动来回切换。
- 工具栏窄屏换行时保留控件归属与顺序，其真实高度计入表格高度预算。
- 固定列宽度需要为中间数据留出可阅读区域，避免首尾固定区重叠或覆盖；窄屏应优先收紧操作区和列宽。
- 上方内容可以精简或收起时优先优化排版，例外模式用于确有需要的较长上方区域。

## 4. 列布局与数据展示

### 4.1 列顺序和固定规则

默认顺序为：名称等识别字段 → 业务字段 → 时间字段 → 操作。

| 项目 | 标准 |
| --- | --- |
| 首个业务列 | 优先名称、标题、姓名等容易区分记录的内容，固定在左侧 |
| 行勾选列 | 业务需要批量操作时才增加；存在时与名称列一起固定在左侧 |
| 尾列 | 一般为操作，固定在右侧 |
| 时间字段 | 集中放在数据列末尾、操作列之前，默认展示“创建时间”“更新时间” |
| 其他业务时间 | 如有发送时间、完成时间等，归入时间区域，置于创建时间和更新时间之前 |
| 列标识 | 每列显式配置稳定、唯一的 `column.key`，包括操作列；数据行另行配置稳定的 `rowKey` |

时间采用统一格式 `YYYY-MM-DD HH:mm:ss`，以页面约定的时区展示。缺失时间显示 `-`，不补造业务时间；是否弱化时间文字取决于其业务重要性。

### 4.2 ID、名称与长文本

- 与阅读无关的数据库 ID、UUID、第三方技术标识不作为独立数据列展示。
- 名称旁可提供复制图标，悬停及键盘聚焦显示“复制 ID”，复制该记录真实 ID。
- 只有剪贴板写入成功才提示“已复制 ID”；失败时提供明确反馈与可行的手动复制方式。
- 业务确实依靠单号、工号等识别记录时，可以展示有明确业务名称的编号列；不把所有带编号的内容一概隐藏。
- 长名称或长文本可省略，悬停或聚焦查看完整内容，保留首列的识别能力。

### 4.3 状态、空值与进度

| 内容 | 标准 |
| --- | --- |
| 成功、完成 | 带中文文字的成功语义 Tag |
| 进行中 | 带中文文字的 processing Tag，颜色跟随项目提示色 |
| 告警、部分完成 | 带中文文字的告警语义 Tag |
| 失败、异常 | 带中文文字的错误语义 Tag |
| 未开始、无效或未知 | 使用中性 Tag，并保留各自真实业务文案，不互相推断 |
| 空字段 | 缺失值、空字符串及纯空白文本统一显示半角 `-` |
| 有效零值 | `0`、`0%` 等保留真实含义，布尔值按业务文案表达，不作为空值 |
| 进度 | 使用进度条并显示百分比；缺少进度依据时显示 `-` |

状态颜色和表格表面读取现有主题，颜色与文字共同表达含义。本次表格状态列明确采用 Tag；后续同步规范时，需补充表格状态列的适用规则，使既有“Tag 用于分类、关键状态使用 Badge 或 Alert”的表述与本要求一致。

### 4.4 操作列

1. 查看、编辑、删除、重发等行操作使用 Ant Design 图标按钮，提供 Tooltip 和可访问的中文名称。
2. 操作数量不超过 3 个时全部显示；超过 3 个时采用“2 个高频操作图标 + `…`”，其余操作进入下拉菜单，使行内入口总数最多为 3 个。
3. `…` 的中文名称为“更多操作”；菜单项同时显示图标和中文名称，危险操作使用危险样式。
4. 删除等破坏性动作提供明确确认。禁用、执行中及失败反馈不只依靠颜色区分。
5. 操作按稳定的业务顺序排列，同类记录保持一致；更多菜单内的操作不得丢失。

“2 个高频操作 + `…`”、时间格式和 60% 的测量口径为本方案的具体实施约定，随本文一起评审。

## 5. 两类工具栏

| 类型 | 左上角 | 右上角 |
| --- | --- | --- |
| 无新增类 | 最多 4 个主要筛选控件，刷新按钮放在该组最后 | 搜索框；多搜索字段使用“条件下拉 + 搜索框” |
| 可新增类 | 搜索框；多搜索字段同样使用条件下拉 | 新增按钮 → 刷新按钮 |

### 5.1 无新增类表格

- 主要筛选按业务使用频率排序，左上角最多 4 个独立业务字段，不因条件增加而持续扩展多行筛选区。
- 第 5 个及之后的条件放到对应列的表头筛选菜单，使用列标题旁的筛选图标打开。
- 例如：状态、类型、负责人、来源放在左上角；部门、优先级放在各自表头。
- 工具栏和列头不为同一字段重复放置两个入口；其筛选值仍统一维护。
- 选中表头筛选后，对应筛选图标反映受控的有效状态；菜单内提供确认与重置。
- 刷新位于左侧筛选组最后，右侧保留搜索区域。

### 5.2 可新增类表格

- 搜索固定在左上角，新增和刷新固定在右上角。
- 新增为主按钮，刷新为次要按钮，顺序固定为新增在前、刷新在后。
- 需要附加结构化筛选时使用对应列表头，保留左侧搜索区域。
- 新增演示仅操作本地示例记录，不访问或写入真实业务数据。

## 6. 受控筛选与排序

### 6.1 同一份状态

| 状态 | 管理内容 | 与界面的关系 |
| --- | --- | --- |
| 搜索状态 | 搜索字段、关键词 | 控制条件下拉与搜索框 |
| 筛选状态 | 以 `column.key` 为索引的有效筛选值 | 同时控制工具栏选值、列的 `filteredValue` 和筛选高亮 |
| 排序状态 | 一个 `columnKey` 与一个 `order` | 派生所有可排序列的 `sortOrder` |
| 分页状态 | 当前页、每页条数 | 控制分页组件和结果范围 |

生效的筛选和排序以页面持有的状态为准，通过 Table 的 `onChange` 回收列头筛选、排序与分页变化。工具栏筛选直接更新同一份筛选状态。

自定义筛选弹层可以暂存尚未确认的输入；确认后写入统一有效状态，取消时不改变当前结果。筛选值清除后，菜单选中态、工具栏和数据结果必须同步更新。

### 6.2 受控属性约束

1. 在列中传入 `filteredValue` 或 `sortOrder` 后，对应能力即进入受控模式，后续交互必须更新状态并重新传回列配置。
2. 所有参与筛选的列持续显式传入 `filteredValue`，空筛选统一为 `null`。
3. 所有可排序列持续显式传入 `sortOrder`。当前排序列使用 `ascend` 或 `descend`，其他列统一为 `null`。
4. “只有一列排序生效”指最多一列具有非空排序方向；其他列保持受控，不通过删除属性或传入 `undefined` 切回非受控状态。
5. 每列显式指定 `column.key`，状态索引、`sorter.columnKey` 和重置操作使用同一标识。
6. 默认值从受控状态初始化，不混用 `defaultFilteredValue`、`defaultSortOrder` 维护另一份有效状态。
7. 本项目规范采用单列排序，不配置多列排序优先级。切换排序列时，一次更新排序状态并清除上一列的方向。

### 6.3 数字字段排序

- 数量、次数、金额、比例、进度等具有数值比较意义的字段均支持升序、降序和取消排序。
- 数字形态的 ID、手机号、工号和业务编码属于标识内容，不因由数字组成而自动作为数值排序字段。
- 按原始业务数值比较，不按带千位分隔符、单位、百分号或格式化金额的展示文本比较，也不采用字符串字典序。
- 进度条按实际百分比数值排序；有效 `0` 与缺失值分别处理。
- 缺失数值升序、降序均置于末尾，不把 `-` 或缺失值转换为 `0`。
- 相同数值保持稳定的基准顺序，取消排序恢复未排序状态下的基准顺序。
- 示例：原始值 `2、10、100、0、空值` 升序为 `0、2、10、100、-`，降序为 `100、10、2、0、-`。

### 6.4 组合与数据处理顺序

- 不同字段的筛选条件取交集；同一字段多选的候选值取并集。
- 搜索结果、工具栏筛选和列头筛选共同生效，再应用唯一有效的数值排序，最后分页。
- 本地演示对完整示例数据使用 Table 的 `onFilter` 和数值 `sorter` 等能力；关键词搜索可预处理完整数据源，不能只处理当前页。
- `filteredValue` 和 `sortOrder` 负责受控状态，数据过滤和排序仍需对应处理函数，不能只改变图标而不改变结果。
- 本次不设计或修改业务查询接口；后续接入远程分页时，另行核实对完整结果集筛选、排序的能力，避免只重排当前页却表现为全局排序。

### 6.5 操作与状态变化

| 操作 | 搜索 | 筛选 | 排序 | 分页 |
| --- | --- | --- | --- | --- |
| 确认或清空搜索 | 更新 | 保留 | 保留 | 返回第 1 页 |
| 修改工具栏或列头筛选 | 保留 | 更新对应字段 | 保留 | 返回第 1 页 |
| 列内重置筛选 | 保留 | 清除该列 | 保留 | 返回第 1 页 |
| 切换数字排序 | 保留 | 保留 | 更新当前列及方向，其他列为 `null` | 返回第 1 页 |
| 清除筛选 | 保留 | 清除所有字段 | 保留 | 返回第 1 页 |
| 重置排序 | 保留 | 保留 | 清空当前列及方向 | 返回第 1 页 |
| 全部重置 | 恢复初始搜索字段并清空关键词 | 全部清空 | 清空 | 返回第 1 页 |
| 刷新 | 保留 | 保留 | 保留 | 保留当前页；结果缩减时校正至有效页 |
| 翻页 | 保留 | 保留 | 保留 | 更新当前页 |

演示初始状态为无搜索、无筛选、无主动排序。清除筛选、重置排序和全部重置按钮放在“受控筛选与排序”章节的演示控制区，不占用两类表格固定工具栏的位置。

## 7. 演示与验收方案

使用同一组本地记录组织两类表格和高度案例。示例覆盖名称、类别、状态、负责人、来源、部门、优先级、数量、进度、创建时间、更新时间及操作；通过足够的列和记录展示横向、纵向滚动。

| 验收项 | 预期结果 |
| --- | --- |
| 常规列表首屏 | 白底容器与分页均处于可见页面底部边界以内 |
| 60% 临界值 | 恰好 60% 使用默认模式；不足 60% 使用例外模式，零记录或少量记录不误判 |
| 吸顶 | 顶部停在固定顶栏下方，完整容器一屏可见，表体内部滚动，能够正常离开表格 |
| 尺寸变化 | 在 1920×1080、1440×900、较矮窗口、缩放及侧栏变化下重新测量，无边界遮挡 |
| 横向滚动 | 首个识别列和末尾操作列持续可见，固定区域不互相覆盖，页面不横向溢出 |
| 工具栏边界 | 4 个条件全部在左上角；增加到 5、6 个时，新增条件位于对应表头，刷新位置正确 |
| 可新增布局 | 左侧搜索，右侧新增和刷新，附加筛选位于表头 |
