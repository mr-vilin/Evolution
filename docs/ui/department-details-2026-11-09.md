# 部门详情抽屉

## 行为

- 组织架构选择普通部门后，在编辑图标右侧提供眼睛图标，打开右侧「部门详情」。失效部门也可查看。
- 上半部分展示部门名称、活跃／禁用状态，以及头像、姓名、部门主负责人／部门副负责人标签；负责人标签与姓名行垂直居中，背景左右采用完整半圆。下半部分依次展示可复制的部门 ID、上级部门、部门群名称、部门群群主。
- 部门群名称右侧提供群 ID 复制按钮，悬停提示「复制群id」。部门 ID、群 ID、列表及成员详情的用户 ID 使用共用 `CopyValue` 弱色图标按钮；复制值分别为实际部门 ID、`chat_id`、`user_id`。已知群 ID 时，即使群名称或群主读取失败也可复制；未返回群 ID 时不提供复制入口。
- 部门 ID 使用目录实际关联的 `feishu_department_id`，即当前集成使用的 `open_department_id`，不将内部 ID 或另一种飞书 ID 命名空间混入复制内容。
- 部门、成员详情共用 `DetailDrawer`。关闭按钮为独立 32×32 控件，分隔线在按钮外，分隔线至按钮间距 16px；关闭、Esc、遮罩及焦点行为沿用 Ant Design Drawer。

## 数据来源与边界

- 管理员 GET `/admin/api/departments/{department_id}/details` 保留现有会话认证与初始化门禁，不需要写入权限。
- 部门名称、状态和层级来自已同步目录；打开详情时通过飞书部门详情接口获取当前负责人列表和 `chat_id`，再通过群信息接口读取实际群名称与群主。负责人和群主优先使用本地用户姓名／头像，目录中没有该用户时只读查询飞书用户详情；无法解析时显示已知用户 ID，不伪造姓名。
- 兼容负责人列表的 `leaderID` / `leaderType` 和 SDK 的 `leader_id` / `leader_type`；1 为主负责人、2 为副负责人，展示顺序为主在前。
- 详情不写入业务数据库、不递增数据版本、不触发同步；没有数据库迁移。群名称和群主不属于已提交目录版本快照，重新打开或「重新读取」可刷新。
- 明确返回空 `chat_id` 才显示「未设置」；字段缺省、权限不足、网络失败显示「暂无法读取」及可重试提示。部门读取失败时保留本地单个主负责人，并标明完整列表暂不可读。
- 本次只针对本地 Docker；未修改测试或正式环境。
