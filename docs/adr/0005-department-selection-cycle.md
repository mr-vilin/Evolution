# ADR 0005：部门勾选采用四步范围切换，并保留部分下级选择

- 状态：交互规则、有效部门选择范围及超过500部门的批量数量已确认；Q9修订为仅计数、直接保存，尚未实现。
- 日期：2026-11-05（北京时间）。
- 依据：[组织树与部门人员浏览需求澄清](../ui/organization-tree-clarification-2026-11-05.md)中的Q5、Q6、Q7、Q9、Q11用户答复。

部门勾选用于批量门店设置，同时需要表达只操作本部门、同时操作下级，以及只操作下级。用户选择四步循环：“均未选 → 仅父部门 → 父部门及全部下级 → 仅下级 → 均未选”，其中全部下级包含尚未在浏览器加载的部门。

手动调整下级时保留实际选择，允许“父部门＋部分下级”，在“本部门及下级”的范围标记中说明“部分下级”。下一次点击父部门只取消父部门，保留下级选择；再次点击才清空该分支。范围是否包含本部门与下级选中是否完整分开表达，避免为了维持全选外观而补选或取消用户已经明确选择的部门。

原生父子级联会使勾选父部门自动代表整个分支，不能表达仅本部门；完全独立勾选又不能提供用户要求的四步分支切换。因此保留应用受控的实际选择范围，用明确中文标记区分范围与完整性，不把Tree原生的checked/indeterminate当作完整业务模型。树是否展开、搜索是否隐藏下级，不改变“全部下级”的业务范围。

【组织】根节点仅全选/清空其下全部有效部门，自身不参与门店设置；失效部门可查询但不纳入批量选择；叶节点仅选中/清空。该决定约束交互与批量目标语义，不预先指定接口序列化或数据库结构；支持超过原500部门上限的完整批量范围，显示去重后的实际选中部门数，组织页批量设置取消影响预览，编辑后直接保存；服务端仍完整校验并保持整批原子提交。
