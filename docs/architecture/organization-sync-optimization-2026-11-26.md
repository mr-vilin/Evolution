# 组织同步与配置中心优化方案

日期：2026-11-26

状态：开发分支已实施，真实环境数据重新核对待验收

适用范围：组织同步首页、同步任务详情、待核实名单、组织管理配置中心，以及相应数据质量和任务统计逻辑。

## 1. 背景与目标

本地最新全量校准任务 `0e1R1WtpzN-O__nc` 于 2026-11-26 11:00:51（北京时间）完成。任务明细共有 945 个部门节点、46 名人员，合计 991 个独立对象，系统却显示已处理 991 / 992、成功 991、失败 0。离职人员贵1（`5g6d8bge`）同时进入成功明细及待核实事实，造成总数重复计算。

此前只读排查还发现 33 个待核实对象全部为人员。32 名在职人员存在选填的门店属性或权限角色空值，另有 1 名离职人员的所属部门未返回。当前事件连接状态依据 90 秒内重连或接收事件的证据计算，页面只有待核实数量而缺少集中核验入口，人员类型和每日核对配置位于系统管理。

本方案统一字段必填口径、数据质量、事件连接规则、任务计数和前端交互。

## 2. 待核实对象

### 2.1 统计口径

当前 `backend/app/admin/sync_views.py` 的 `sync_summary` 实时计算下列三个集合的并集数量。

| 来源 | 条件 |
| --- | --- |
| `employee` | `sync_quality = 'pending_verification'` |
| `department` | `sync_quality = 'pending_verification'` |
| `org_pending_fact` | 存在尚未解除的待核实事实 |

按对象类型和对象 ID 去重。沿用该方式，数量和名单共用同一查询条件与对象身份口径。新增待核实原因的持久化设计应复用现有待核实事实，不重复生成对象；必要时补充结构化原因字段及迁移。

### 2.2 人员字段规则

| 字段 | 要求 | 校验规则 |
| --- | --- | --- |
| 人员 ID | 必填 | 非空、有效且与请求标识一致 |
| 姓名 | 必填 | 非空、符合长度约束 |
| 手机号 | **必填** | 必须返回可读取的合法非空手机号，支持飞书实际使用的合法号码格式 |
| 人员状态 | 必填 | 具有可验证的离职或退出状态，保留其他账号状态原始事实 |
| 所属部门 | 条件必填 | 正常激活人员须返回可读、格式有效的部门列表，允许明确返回空列表 |
| 主部门 | 条件必填 | 人员有所属部门时，须有且仅有一个有效主部门 |
| 人员类型 | 选填 | 空值或省略允许，已填写的枚举值按已配置选项处理 |
| 工号、职务、直属上级 | 选填 | 空值或省略允许 |
| 权限角色、门店属性 | **选填** | 空值或省略允许，字段定义和选项配置须有效 |
| 邮箱、头像、入职日期、登录标识 | 选填 | 空值或省略允许 |
| 暂停、激活、未加入等状态标志 | 可缺省 | 未采集时保留未知状态，依据明确的状态事实判断豁免 |

手机号适用所有人员状态，当前未另行设定手机号豁免。所属部门的空值与未返回语义须区别处理。

| 账号事实 | 部门列表未返回 | 处理规则 |
| --- | --- | --- |
| 正常激活 | 待核实 | 保留有效历史关系，等待重新读取 |
| 未加入 | 正常 | 缺少部门关系属于允许的情形 |
| 未激活 | 正常 | 缺少部门关系属于允许的情形 |
| 已离职 | 正常 | 同步离职状态，结束有效历史关系 |
| 已退出 | 正常 | 同步退出状态，结束有效历史关系 |
| 状态未知，无法确认豁免 | 待核实 | 依照必填关系规则判断 |

未激活以 `is_activated = false` 为依据，未加入以 `is_unjoin = true` 为依据，离职及退出以相应状态标志为依据。有效账号的部门列表明确为空时允许无部门。已返回的必填关系必须可解析且一致。选填字段格式异常时保留可用的历史值，记录字段级异常供排查。

### 2.3 部门字段规则

| 字段 | 要求 | 校验规则 |
| --- | --- | --- |
| 部门 ID | 必填 | 非空且与请求标识一致 |
| 部门名称 | 必填 | 非空、符合长度约束 |
| 部门状态 | 必填 | 删除状态可读 |
| 上级部门 | 条件必填 | 根部门可无上级，其他有效部门须引用有效上级 |
| 部门负责人 | 选填 | 允许为空或省略 |

已删除部门缺失上级时保留历史引用，同步删除事实。全量扫描中已知对象缺席且无法证明其真实状态时，继续进入待核实，保留历史资料。

### 2.4 校验与核验入口

初始化预检、初始化同步、全量同步、全量校准、局部同步和事件同步共用字段要求及状态豁免判断。必填字段缺失、不可读、无效，或必填关联无法确认，才进入对象待核实名单。已配置的选填字段未返回，正常情况下视为可空。

组织同步页点击待核实数量打开名单。列出名称、对象类型、待核实字段、原因、最近同步时间、查看对象操作。支持按对象类型及异常原因筛选，按名称或业务标识搜索。名称旁提供对象 ID 复制入口，未入库对象显示来源 ID 及可用名称。

管理员根据原因去飞书核验缺失的必填资料或读取权限，再执行同步。后续有效同步自动解除相应待核实事实。手机号必填规则新增后，需要依据重新采集的资料核对实际数量，因此此前 33 个对象不能直接认定全部清零。

## 3. 飞书事件连接与配置中心

### 3.1 连接状态计算

最近一次有效通讯录事件的服务端接收时间作为计算依据，重连、接口全量读取和进程启动均不更新该时间。有效事件包括受支持的人员、部门新增／修改／删除及通讯录授权范围变更事件。事件校验、落库成功后记录接收时间，保存与实际事件接收保持一致。

| 状态 | 默认时间条件 | 语义色 |
| --- | --- | --- |
| 正常 | 距最近接收时间 ≤ 60 分钟 | 绿色 #52C41A |
| 告警 | > 60 分钟且 ≤ 180 分钟 | 告警色 #FAAD14 |
| 断开 | > 180 分钟 | 错误色 #FF4D4F |

无历史事件时，自启用监测时间起计时，180 分钟内显示告警，超过断开时限显示断开。未配置飞书应用时显示未配置。该状态描述业务事件接收时效。事件处理结果单独记录，已经收到的事件即使后续业务处理失败也保留接收时间。

最近事件接收时间及启用监测时间持久化保存，服务重启、连接恢复和刷新页面后继续计算。状态计算使用服务端 UTC 时间，展示采用北京时间。修改阈值保存后即时生效。

组织同步首页展示状态点、状态文字、最近事件接收时间、距今时长及进入配置的入口。系统管理中的飞书连接摘要如保留，状态口径也须一致。

### 3.2 组织管理配置中心

在组织管理下新增「配置中心」，复用现有 Ant Design Pro 布局及权限边界。组织架构、组织同步和组织变更记录菜单继续存在。配置中心页采用三个页签。

| 页签 | 功能 |
| --- | --- |
| 人员类型 | 将管理设置中的人员类型维护迁移至此，沿用原有选项、校验及保存接口 |
| 每日核对 | 迁移现有启用开关、北京时间执行时间、时区及更新时间 |
| 飞书事件连接 | 维护正常时限、断开时限，展示当前状态及最近有效事件接收时间 |

事件配置使用带分钟单位的数字表单，默认正常时限 60 分钟、断开时限 180 分钟。两者须为正整数，断开时限大于正常时限。配置由后端校验并持久化，管理员保存后查看实际生效值。采用现有系统配置机制，优先复用已存在的设置存储及审计能力。

## 4. 全量校准任务计数

### 4.1 统一计数

任务的对象身份为（对象类型，对象 ID）。构建本次尝试的最终对象集合，合并部门候选、人员候选、待核实事实及分批处理的对象，只为同一对象保留一条最终处理结果。

| 指标 | 规则 |
| --- | --- |
| 总数 | 本次任务发现的独立对象数量 |
| 成功数 | 最终成功处理的独立对象数量 |
| 失败数 | 必填信息或必填关系存在未解决问题、最终处理失败的独立对象数量 |
| 已处理数 | 成功数 + 失败数 |
| 未处理数 | 总数 − 已处理数 |
| 进度 | 总量已知时为已处理数 / 总数 |

采集过程中可显示独立的采集快照及已提交批次，最终发布时以本次尝试的唯一对象明细汇总。对于同一对象成功同步账号状态、必填关系仍存在异常的情况，按最终失败一次计数，同时详情保留已成功提交的变更。已提交批次的回执和变更记录可追溯。

正常终结条件为全部对象已有最终结果，成功加失败等于总数。任何未处理对象仍存在且任务无法继续时，任务失败并记录原因。合法的状态豁免及选填空值正常成功。

| 展示状态 | 判定 |
| --- | --- |
| 完成 | 已处理等于总数且失败为 0 |
| 完成（有异常） | 已处理等于总数且存在失败对象 |
| 失败 | 执行失败、中断，或仍有对象未处理 |
| 执行中 | 任务尚未终结 |

计数与终态在最终发布事务内一致提交。沿用现有租约、分批入库、重试及版本约束，避免旧尝试覆盖本次结果。同步明细和任务摘要必须一致，任务详情中可看到真实失败原因或尚未处理的对象。

在上述最新任务中，重复对象去重后总数为 991。原执行记录对应成功 991、失败 0，按新规则重新采集后成功失败数还需核对手机号及其余必填字段。历史任务修正通过可审查的迁移或受控修复程序计算，只有明细证据足以重建计数时才修正，保留原始历史与修复审计。
