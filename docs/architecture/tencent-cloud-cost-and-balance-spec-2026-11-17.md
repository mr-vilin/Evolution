# 腾讯云成本分析同步与实时余额查询规格

日期：2026-11-17。项目：Evolution。目标跟踪器：`mr-vilin/Evolution` 的 GitHub Issues；分流标签：`ready-for-agent`。

业务问题 Q1–Q6 均已答复，测试边界已确认。本规格依据本次会话、《腾讯云成本分析定时接入与余额实时查询方案》《腾讯云通用同步模型与成本覆盖示例》《腾讯云接入设计审查与决策记录》及领域词汇整理。ADR 0004 的组织初始化清理边界、ADR 0006 的费用与余额保留规则继续适用。此前最终共同理解及开始应用实现的确认仍保留为实施前置项；本次调用 `to-spec` 授权整理和发布规格，不替代该确认。

## Problem Statement

管理员需要在 Evolution 中按账号、月份和产品查看腾讯云费用，并在需要时查询账户当次余额。目前系统只有飞书组织相关的采集与管理能力，没有腾讯云账号管理、成本数据集或余额查询能力，管理员仍需进入腾讯云控制台核对。

原方案把余额当作定时采集业务，会把旧状态误当作当前可用资金；成本若只追补新日期，会漏掉迟到费用、退款和调账。官方可查询历史也未必覆盖账号全部账期，不能把取回近期数据宣称为全历史完成。新增财务能力还需要明确账号归属、管理员权限、组织初始化门槛，以及任务失败、重试和恢复时的数据一致性。

## Solution

提供独立的云成本看板、腾讯云账号管理和结构化同步配置。成本通过官方接口按日、周或月采集，自动复核近期账期，按完整期间替换当前产品结果；管理员能够查看覆盖、缺口、最近成功时间、任务及逐次尝试，并手动重拉更早历史。无法取得的旧账明确保留缺口，近期数据先投入使用。

余额在进入余额页面或手动刷新时直接向腾讯云查询，以真实可用余额为主指标，现金、赠送、冻结、欠费和信用额度分别展示。显示本次查询时间，失败明确提示，旧结果不得冒充实时数据；不设置余额同步任务或余额历史表。

整个腾讯云模块仅向现有管理员白名单开放，且必须完成组织初始化。每个独立腾讯云账号使用自身只读凭据并查询自身费用和余额。沿用当前技术栈和部署拓扑，云产品仅预留扩展。

## User Stories

1. 作为管理员，我希望在组织初始化完成后进入腾讯云模块，以便在系统达到既定可用条件后使用云财务能力。
2. 作为管理员，我希望组织初始化未完成时页面、接口和后台任务统一受限，以便页面入口与实际执行资格一致。
3. 作为普通组织目录查看者，我希望系统对财务入口和接口执行访问控制，以便我的组织目录权限不会意外获得财务数据。
4. 作为管理员，我希望分别执行费用查看、导出、账号维护、配置维护和手动重拉，以便各项操作有明确的服务端权限检查和记录。
5. 作为管理员，我希望登记多个独立腾讯云账号及中文别名，以便分别识别各账号的费用和余额。
6. 作为管理员，我希望从受控选项绑定账号的只读凭据引用，以便不用在浏览器或普通配置中保存可用密钥。
7. 作为管理员，我希望账号注册和凭据轮换验证实际归属，以便避免一个账号的凭据关联到另一个账号的财务数据。
8. 作为管理员，我希望停用账号后阻止该账号的新查询、任务领取和在途新结果发布，以便账号总开关具有一致效果。
9. 作为管理员，我希望只登记账号而不开通成本同步也能查询其余额，以便余额查询不依赖成本配置。
10. 作为管理员，我希望进入余额页面时查询腾讯云当次返回的账户状态，以便获得当次可见的可用资金信息。
11. 作为管理员，我希望手动刷新余额并看到本次查询时间，以便判断金额的新鲜程度。
12. 作为管理员，我希望余额主卡展示 RealBalance 真实可用余额，以便使用已确认的主指标判断账户状态。
13. 作为管理员，我希望现金余额、赠送余额、冻结、欠费及信用额度分别展示，以便理解不同资金口径。
14. 作为管理员，我希望金额明确标注币种和单位并精确换算，以便避免把分当作元或混合不同币种。
15. 作为管理员，我希望余额超时、权限不足和账号不符时得到明确错误，以便知道本次查询没有成功。
16. 作为管理员，我希望查询失败时旧值不会被标为实时余额，以便不会据过期结果做判断。
17. 作为管理员，我希望为每个账号的成本分析独立设置频率、时刻和启停，以便各账号按自身需要运行。
18. 作为管理员，我希望全部配置使用中文结构化表单并有字段校验，以便无需编写或粘贴 JSON。
19. 作为管理员，我希望首次采集回溯所有实际可取得的到期历史，以便尽可能建立既往费用视图。
20. 作为管理员，我希望近期范围优先可用，旧账缺口单独显示，以便历史不可查不会阻塞近期看板。
21. 作为管理员，我希望区分最早已核验账期、连续覆盖、近期覆盖和缺失区间，以便理解历史完整程度。
22. 作为管理员，我希望按日模式采集截至昨日的完整自然日，以便执行当天的未完成数据不混入费用范围。
23. 作为管理员，我希望按周模式在每周日执行并补齐截至昨日的缺失日期，以便按既定周期更新费用。
24. 作为管理员，我希望按月模式在每月 3 日新增上一个完整自然月，以便按已到同步日的账月查看费用。
25. 作为管理员，我希望月模式在每月 1–2 日手动触发时也遵守到期边界，以便不会提前把上月视为已具备同步条件。
26. 作为管理员，我希望日或周任务自动复核当月截至昨日及上月，以便已采集日期的迟到费用和调账能够更新。
27. 作为管理员，我希望月任务复核最近两个已到同步日的完整账月，以便近期历史更正得到自动反映。
28. 作为管理员，我希望指定更早期间或全部实际可取历史手动重拉，以便处理自动复核窗口以外的更正。
29. 作为管理员，我希望任务失败或停机后补齐缺失期间，以便漏跑不会永久丢失费用。
30. 作为管理员，我希望频率切换后保留已有完整数据并避免日/月重复，以便看板不会重复计费。
31. 作为管理员，我希望完整重拉覆盖该期间全部产品并移除源端已消失的产品，以便当前费用集合与本次成功响应一致。
32. 作为管理员，我希望每个账期保留当前一份费用，其他月份保持完整，以便更正历史金额时不会误删其他账期。
33. 作为管理员，我希望采集或提交失败时保留原费用，以便仍能读取上次完整成功结果。
34. 作为管理员，我希望真实零费用与无权限、未准备、空页或历史不可查分开，以便错误不会把旧费用清零。
35. 作为管理员，我希望重复提交和自动重试不会重复写入费用，以便重启或网络重试不造成重复计数。
36. 作为管理员，我希望每次重试有独立的输入、返回和失败记录，以便追溯执行过程而不是只看到次数。
37. 作为管理员，我希望任务受理后能获得任务编号并查询进度，以便区分受理成功与执行完成。
38. 作为管理员，我希望批次清楚展示成功、部分成功、失败或阻断，以便一个期间成功不会掩盖其他期间缺口。
39. 作为管理员，我希望不同账号独立运行且遵守接口限流，以便一个账号失败不会串改其他账号的数据或状态。
40. 作为管理员，我希望停用成本配置后仍可查询该账号余额，以便采集业务开关不会意外关闭其他独立能力。
41. 作为管理员，我希望在成本看板按账号和月份查看趋势、总额及产品月度表，以便理解费用变化。
42. 作为管理员，我希望图表可展示 Top10 加其他，表格和导出包含全部产品，以便展示简洁且对账完整。
43. 作为管理员，我希望未映射和同名歧义产品清楚显示，以便不会因名称相同而错误合并费用。
44. 作为管理员，我希望缺失、尚未到期、当前月累计及有效零金额各有明确展示，以便不会把不同状态都理解为零费用。
45. 作为管理员，我希望环比、同比只在覆盖完整、口径一致且分母有效时计算，以便不会把部分月份或缺失数据包装成费用下降。
46. 作为管理员，我希望总额、产品明细和覆盖状态来自一致的数据读取，以便不会看到替换期间的中间状态。
47. 作为管理员，我希望恢复或初始化世代变化后旧任务和旧余额响应失效，以便恢复前的执行不会污染当前状态。
48. 作为管理员，我希望初始化失败重来保留腾讯云账号、配置、费用及执行证据，以便组织数据清理不会误删独立云财务资料。
49. 作为管理员，我希望正常组织发布保持有效腾讯云任务继续运行，以便组织更新不会无故中断财务采集。
50. 作为管理员，我希望查询、配置和重拉保留必要审计且不泄露密钥或整批账单，以便排障和访问追溯兼顾财务信息保护。

## Implementation Decisions

1. **模块与既定架构。** 新增腾讯云账号与凭据解析、官方 API 适配、采集配置、调度与执行、成本处理器、成本查询及实时余额查询能力。前端沿用 React、TypeScript、Umi Max、Ant Design Pro 和项目设计规范；后端沿用 FastAPI、Pydantic、SQLAlchemy、Alembic 与 MySQL 8.4。云 worker 在现有合并部署容器内受监督运行，不复用飞书组织采集器及其全局单例租约作为云业务调度器。
2. **身份与业务动作。** 只使用现有管理员白名单及会话体系，不新增财务角色分配。成本查看、导出、账号维护、配置维护、余额查询和手动重拉分别登记动作并在服务端检查。普通组织查看者和既有机器身份不因此获得财务权限；写操作保留现有 CSRF 等安全校验。未来新增动作不能因历史通配符自动授权。
3. **初始化门槛。** 全模块以 DatasetState 单例的 initialization_status 为 complete 为准，覆盖页面、查询、配置、人工受理、调度、领取、执行和提交。逻辑任务受理时冻结 dataset_epoch，每次尝试保持原值；提交事务按一致锁序复核 complete、epoch、账号/配置开关及租约。余额返回前复核同一世代及账号资格；前端收到 INITIALIZATION_INCOMPLETE 时刷新门禁并停止展示业务内容。
4. **恢复与组织清理。** 组织失败重来不扩大清理到腾讯云数据。恢复或失败重来改变世代后，保留云账号、配置、费用及任务证据，终结或阻断旧活动资格，旧任务不能重新绑定新 epoch；初始化重新完成后以新世代补齐所需期间。普通组织发布保留已有 epoch，不误阻断合法云任务。不新增日常整库重新初始化入口。
5. **账号与秘密。** 腾讯云账号的 UIN 作为不可重新绑定的身份字符串保存，别名可维护；每个账号使用自身只读子用户或角色凭据。数据库仅保存后端受控解析的 credential_ref，用户不能任意读取文件路径或环境变量。注册、轮换及查询验证归属，余额逐次核对返回 UIN；成本归属与已验证账号一致。账号总开关与在途发布协调，不通过修改 UIN 转移既有费用。
6. **实时余额。** 查询服务直接调用 DescribeAccountBalance；RealBalance 为主卡，现金、赠送、冻结、欠费和信用额度分别展示，不互相替代或合并。进入页面及手动刷新触发查询，具有超时和限流，不自动轮询；显示成功时间，失败返回明确错误。余额不创建采集配置、任务、尝试或历史余额结果；必要的请求审计独立于任务模型，默认不复制余额正文。
7. **成本数据源与口径。** 首选官方 DescribeCostExplorerSummary，采用费用账单 BillType=1、总费用 FeeType=cost、产品 Dimensions=business，按真实日或月粒度采集；product 指子产品，不能混为同一口径。按完整分页获取全部产品，必要时使用口径一致的 DescribeBillSummaryByProduct 辅助对账；摊销消耗视角不混入本期指标。官方 Python SDK 在实现时验证 Python 兼容性并锁定版本，依赖清单与锁文件同步。
8. **日期与调度。** 费用期间按 Asia/Shanghai 的自然日/月及半开区间表达；调用上游时转换为其要求的边界格式。运行、审计及数据库执行时刻沿用 UTC。日模式每天、周模式固定周日、月模式固定每月 3 日。默认时刻仍为设计建议 13:30，可在结构化表单修改；未创建实际任务。日/周截至昨日，月模式只纳入已经到同步日的完整账月，每月 1–2 日最多到上上月。
9. **新增、复核与补漏。** 日/周每次重查当月截至昨日及上月；月模式每次重查最近两个已到同步日的完整账月。例如 12 月 3 日新增 11 月并复核 10、11 月，不含 12 月 1–2 日。新增和复核重叠期间只入队一次；更早失败期间继续补漏，无法取得的历史显式标记，不无限重试。手动重拉支持指定范围或所有实际可取历史，遵守所选模式的到期边界，未重采的历史不保证永久与源端一致。
10. **历史与覆盖。** 首次尽可能回溯全部实际可取历史，近期优先，旧账有界排队。分别表达已核验历史起点、回溯目标、缺口、近期实际覆盖、连续覆盖和最近成功时间；连续边界不跨缺口，近期可用数据不因早期缺口停滞。不能以接口空结果证明没有历史费用，也不能以近 6 或 12 个月替代全历史完成。历史原始粒度保留，月汇总不能拆成虚构日数据。
11. **六个逻辑实体。** 通用基础实体为 tencent_account、tencent_sync_config、tencent_sync_job、tencent_sync_attempt；成本结果为 tencent_cost_period、tencent_cost_item。账号不承载某业务频率或进度；配置按账号与采集业务唯一，账号和业务绑定不可修改。余额查询不进入采集模型，cloud_product 仅预留受控扩展码，处理器未实现不得启用。配置默认关闭，启用前校验参数、业务能力及执行策略。
12. **配置与快照。** 配置具有并发修订号；专用参数、进度及执行策略由明确的类型模型校验，内部可用 JSON 保存，界面使用中文结构化表单。逻辑任务冻结配置修订、处理器契约、可信发起身份、账号/业务、范围、口径、策略及初始化世代。配置编辑影响新轮次，重试不能扩大范围或采用最新配置冒充原输入；当前开关、授权及安全的凭据轮换仍实时核验，不冻结过期权限。
13. **批次与期间任务。** 同一任务实体区分纯汇总父批次和实际执行的日/月期间子任务。父批次不领取租约、不伪造处理器调用；期间各自完整采集、校验和事务提交。全部子任务成功父批次才成功，部分失败、缺口及阻断可见。空范围返回明确的无待同步状态，不伪造费用或执行尝试。
14. **幂等与租约。** 按配置及 idempotency_key 去重。父批次以固定世代和计划执行点或人工提交身份确定；期间子任务在原批次快照下增加粒度、起止和口径，父子命名空间分开。相同事件重复受理先定位原批次，不因配置已编辑而重新计算范围。新世代补漏使用新身份；费用期间唯一键不加 epoch。同配置只有一个实际期间任务持有串行资格，重试等待期间保留该资格；独立配置允许并行，仍受接口及身份限流。提交核对 active_job_id、租约所有者、期限和代数，旧执行者不得覆盖新结果。
15. **运行治理。** 任务固定截止、尝试预算、单次及轮次预算、退避、租约/心跳、有界队列和补跑限制。仅对可安全重复的临时故障重试，权限、参数和账号错误不能盲重试。停机恢复合并补齐所需期间，不逐个重放所有已成功的旧计划点。运行参数和尝试/日志留存值在实现时登记并验证，不套用组织 worker 常量作为已验证云业务默认值，不自动启用历史清理。初始化未完成或无可执行配置时空闲，凭据故障只影响对应任务。
16. **执行尝试与真实返回。** 每次实际执行先可靠保存完整脱敏有效输入，再调用处理器；每次重试新增尝试，不覆盖先前记录。保存独立状态、原因、执行者、世代、时间、隔离代数、请求标识、捕获形态和实际返回。成本处理器真实最终返回定义为提交回执、成功期间 ID、条数及请求标识，并完整保存；内部分页账单不是最终返回，不复制成费用历史。成功返回及尝试状态与费用同事务记录；失败证据独立于费用回滚。提交结果不明时先核对原任务/尝试及期间提交事实，不能仅因回执保存问题重放已确认业务。
17. **费用期间与当前值。** 每个账号的日/月期间唯一，期间内产品行唯一；每个账期保留当前一份全产品结果，不建立费用版本或长期原始响应副本。期间记录总计、币种、来源粒度、产品数及最近成功任务/尝试；来源必须属于同账号成本配置。一次只覆盖本次期间，不误删其他月份。内部执行记录不得构成第二套旧费用数据。
18. **完整期间事务替换。** 在事务外完成该期间全部分页与完整性校验，再在短事务中锁定相关状态与配置、复核资格，删除该期间全部旧产品、写入完整新集合、更新总计、提交回执、尝试、任务和配置进度。失败回滚保留原费用，源端消失产品一起移除。公共状态和账号检查可使用共享锁，避免不同配置被全局排他锁串行。查询总额、产品与覆盖在一致性读取中完成，不暴露删除和插入之间的中间态。
19. **日/月互斥。** 同一账号同一自然月只能保存完整月记录或不重叠日记录，唯一键之外还须在成本配置锁下校验范围。日/周切月时，完整月取回并通过校验后同事务替换该月所有日数据；切回日/周保留已有完整历史月。重拉范围命中月记录时明确展示实际整月范围，按整月覆盖，不叠加若干日金额。
20. **分页与有效零值。** 检测重复页、提前空页、条数变化及总计不一致，失败时不发布半份结果。主接口没有通用就绪标志；只有已核验账期可查且数据就绪、全分页与总计确认有效零值时才允许清除旧非零数据。辅助接口 Ready=0 时退避重试；未确认就绪、权限失败、历史不可查及解析失败保留旧结果并报告。没有跨页一致性令牌时不宣称源端事务快照，必要时重读总计复核。
21. **金额与产品身份。** 余额官方单位为分，部分字段声明 Float，必须在原始 JSON 数值解析边界保留十进制精度，不能先过二进制 float 再声称恢复。后端金额使用 Decimal，对外用明确币种及单位的十进制字符串；成本拟使用有符号 DECIMAL(24,8)，须以真实精度定稿，超精度拒绝而非静默截断。退款负值保留，多币种不能直接合计。产品维度使用可靠匹配的 BusinessCode，持久字段为 business_code，不与子产品 ProductCode 混用；未映射或同名歧义行保留原始名及期间内标识，禁止凭同名跨期静默合并。
22. **页面与导出。** 提供账号、月份范围、月度趋势、产品月度表、总额、口径、成功时间、任务和缺口。月模式当前月标待下月 3 日同步；日/周当月标累计截止日及未完整状态，缺失不显示为零。图表可 Top10 加其他，表格及导出完整。环比和同比要求完整可比覆盖及一致口径，缺失或零分母显示不可计算。账号页进入余额查询，采集配置列表没有余额行或立即同步余额动作；单独停用成本不关闭余额。
23. **接口与审计。** 沿用现有 HTTP 成功/错误契约和会话机制，可靠受理成本任务后返回任务编号及查询方式，不把受理等同最终成功；配置并发冲突、初始化未完成、无权限、未准备及上游故障有明确分类。财务响应使用 Cache-Control: no-store。每个实际入站请求各计一次，分页调用、逻辑任务和尝试分开统计；关联操作者、账号、动作、时间、状态及请求标识。仅保留必要白名单摘要，不默认存余额正文、整批账单或可用秘密，不把现有业务变更日志当作已具备完整请求审计。
24. **CAM 与联调。** 各账号最小只读动作包括 finance:DescribeCostExplorerSummary、finance:DescribeAccountBalance；实际采用辅助对账再授予对应动作。这些动作是操作级、资源为 *，不假设支持 IP 条件或任意 UIN 查询。不要求本期集团授权。真实身份、权限、单位/币种、小数精度、时间/粒度、产品字典、零账单及最早可查询历史都须只读联调，不把公开示例或用户业务选择当作真实样本证据。
25. **数据库交付。** 按项目 MySQL 8.4、InnoDB、utf8mb4、utf8mb4_general_ci 设计，稳定标识按项目二进制比较约定；关联 ID 类型一致，由应用保证本期关系完整性，不新增物理外键。表和每个字段添加非空中文注释，SQL、ORM 和 Alembic 生成结果一致，迁移提供执行前检查、执行后验证及恢复说明。不修改既有组织表或排序规则。执行前核实实际环境 schema、版本和会话，不能仅凭配置或示例 DDL 宣称已经生效。
26. **实施前置与交付。** 本规格发布不开始应用实现，不执行数据库迁移、真实写入或部署。此前最终共同理解及开始实现的待确认项继续保留。后续实现按已确认范围完成验证；数据库实际操作和部署按当次授权，代码测试通过不自动重部署 Docker，测试/正式环境须明确指定。沿用统一发布流程，不为此功能新增部署拓扑。

## Testing Decisions

- **用户已确认的主边界。** 使用完整应用的管理端 HTTP API 与实际任务执行作为主要行为验收入口，连接隔离 MySQL 8.4；只在腾讯云出站边界提供可控响应，覆盖分页、回补及故障，不 mock 成本业务服务、调度器、租约或持久化结果。通过 HTTP 任务查询、费用查询、导出、审计和必要的已提交数据库事实观察结果，不断言私有函数或 SQL 调用顺序。
- **少量页面验收。** 补实时余额进入/手动刷新/失败、组织初始化门槛、覆盖缺口与结构化表单等关键页面流程。沿用现有 Vitest、Testing Library 及按需浏览器验证，不将每个内部组件复制成独立的测试层。
- **沿用的测试先例。** 现有 HTTP 契约测试已使用 FastAPI TestClient 和身份依赖替换，初始化向导测试覆盖 CSRF、门禁与失败不发布；MySQL 事务、队列及恢复测试已有回滚、租约和世代隔离案例；飞书适配器测试已有出站响应控制及重复分页检测；同步页与 AuthGate 的界面测试已有用户操作及状态展示先例。复用这些边界和隔离习惯，腾讯云仅补一个出站传输适配点，不为每个业务方法新增 mock 层。
- **真实并发证据。** 普通 MySQL 回滚夹具绑定单连接，不能证明多 worker 抢占和锁行为；竞争、租约过期、恢复与提交竞态必须使用独立连接。可沿用隔离评测的专用测试库、实际版本/会话核验、独占生命周期和 finally 清理模式，并补齐腾讯云 worker 静默与停止条件；不能在活跃 worker 运行时 reset。仅允许显式登记的 _test 库，不清理开发业务库、测试环境业务库或生产库。
- **控制时间与故障。** 用明确执行时刻和有界运行驱动实际调度/worker，不等待真实日、周或月流逝。模拟上游使用原始 JSON 数字字面量，以便验证 Float 字段解析精度；故障注入只作为输入或运行条件，断言外部可观察结果。数据库迁移及事务必须使用真实隔离 MySQL，SQLite、离线 SQL 和内存假数据不替代此证据。

| 场景 | 触发及应观察到的结果 |
| --- | --- |
| 权限与初始化 | 匿名、普通查看者及初始化未完成管理员访问被正确拒绝；页面隐藏不能替代 API 拒绝，自动任务也不运行；写操作继续校验 CSRF |

| 实时余额与精度 | 进入/刷新触发当次外部请求，分精确转元、各金额分别展示、时间准确；超时/无权限不冒充成功，不新增余额配置、任务或结果历史 |
| 日期与频率 | 日截至昨日、周日及每月 3 日、跨年/月末、1–2 日手动触发和跨日重试都保持固定正确范围 |
| 历史与缺口 | 不可查旧账不能标全历史成功，近期仍可使用；最早已核验范围、缺口和连续覆盖互不混淆 |

| 可靠受理与幂等 | 重复计划点、手动请求重试、重启及配置编辑不重复生成原事件；新世代补漏不被旧键阻止，受理返回不冒充最终成功 |
| 批次与尝试 | 部分期间失败时父批次不能成功；每次重试有独立真实输入/返回或失败事实，父批次没有虚构尝试 |
| 完整替换与回滚 | 产品消失后无残留，负值保留；提交失败仍见旧完整费用，其他账期不变，成功回执与当前费用一致 |
| 零值及分页异常 | 重复页、提前空页、变动总计、未准备或权限错误均不清空；经过核验的零费用可替换旧非零结果 |
| 日/月切换 | 日转月事务替换，月转日保留历史完整月，命中月记录的日范围重拉按整月解释，任何查询不重复求和 |
| 租约和提交竞态 | 同配置互斥，独立配置可推进，旧租约失去提交权；停用与在途提交按已确认边界处理 |
| 世代变化 | 恢复或失败重来阻断旧任务/余额响应，云数据保留，新世代可补漏；普通组织发布不误阻断合法任务 |
| 查询与导出 | 总额、完整产品和覆盖来自一致读，Top10 仅影响图表；缺失与零值不同，不完整月不伪装成同比/环比下降 |
| 审计与秘密 | 入站实际请求、外部分页、逻辑任务和尝试计数正确区分，可关联排障；响应、配置及记录不泄露密钥或整批财务正文 |
| MySQL 与迁移 | 实测版本、结构、会话、字符集、字段中文注释、唯一性、回滚及恢复，不能仅检查 ORM 或迁移文本 |

- **真实来源验收另列。** 在真实只读身份可用且相关操作获得授权后，对照同账号、同口径、同时间范围的腾讯云结果，验证一个完整账月、当前月截至昨日、全部产品、历史边界及一次余额查询；记录脱敏证据。实际持久化和定时触发另按实施阶段授权验证。模拟响应测试通过只说明本地处理行为，不能证明 CAM、真实历史范围或源端账单一致性。本轮仅约定这些测试，未执行应用、MySQL 或腾讯云验收。
