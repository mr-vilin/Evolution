# 腾讯云 T08 历史发现、缺口与范围重拉

日期：2026-11-17（Asia/Shanghai）。对应 Issue #23；基于 `44ee7b2f9e0f66dfa91ed8969a2b476c88d02e61`。遵循父规格、ADR 0004/0006、项目数据库/API/权限/调用审计/日志/调度及前端规范。这里只记录实现及隔离验证，未进行真实腾讯云、业务数据库迁移或部署。

## 历史语义与来源边界

配置新增受 `HistoryProgress` 类型校验的内部 JSON 检查点，保存来源依据、发现事件序号、原父事件及目标起止；版本、日期、范围和额外字段严格校验。已有 null 配置保守加载，不伪造历史起点。成功覆盖、最近成功、失败和预算从持久 period/job/attempt 事实计算，不复制旧费用或上游报文到进度。仍然只有原六个财务逻辑实体。

公开日 6 个月、月 12 个月是来源能力窗口，不是账号首账期。目前没有已核验的首账期 API，故账号发生起点始终明确未知、更早范围待评估；完成本轮目标也只称“已知来源目标已探测”。日窗口精确边界未经真实联调；采用最近六个自然月内完整日区段，边界旧月和其余月窗口内旧账以来源完整月探测，保留原始粒度，不分摊假日值。

首次实际计划先受理近期；之后配置锁内建立 `history:{epoch}:{sequence}` 持久父事件，每片最多月 12 / 日周 31 个原始期间。一片结束后继续；首个空月、权限错或未就绪不会阻止更早尚未探测期间。来源窗外不自动无限回扫。普通计划继续规定近期和有界真缺口，已覆盖历史不反复全采。`manual` 配置只推进管理员已受理范围，不擅自转成自动发现。

费用事实跨 epoch 保留；新 epoch 只复核近期或补真实缺失，旧活动 job 不重绑。覆盖以已提交同口径期间为准，连续区间遇洞即停，最早零散成功不当连续起点。已有整月在日模式目标中按整月计数，月覆盖不冒充原始日值。

已探测缺口保留稳定原因（权限/未就绪/零未确认/参数/临时/未知上游）、最近探测、自动预算与窗口外说明；尚未探测与延期分别表达。旧账自动失败最多三个真实自动轮次，按配置、实际期间和凭据修订累计，跨 epoch、频率修改、重启仍有效；人工失败和取得执行资格前的拒绝不消耗来源预算，人工明确新键可重新探测。没有可靠证据时不宣称“无账单”或“已确认不可查”。

## 队列与执行

近期与历史使用数据库领取优先级和索引。每配置独立候选，通常四次近期后给历史一次份额；当前 active retry 保持互斥及原预算。配置间以最近实际 attempt 序列公平领取，不因 A 大 backlog 挡住 B。既有旧待执行队列迁移时只补优先级，不改 snapshot/epoch，不复活任务。月度/人工按每月 3 日门槛保留最近两个已到复核日期的月份；日/周保留当月和上月，不能把月度第二个近期月误归历史。

队列上限仍允许 1..500。历史自适应预留近期容量，最多预留队列的一半；空队列至少可推进一个期间。近期本身超过小队列时先受理可容纳片，后续持久发现补齐，不永久429。历史不无限追加，原 run/attempt 的截止、重试、当前初始化/管理员或系统身份、账号/凭据安全修订、配置控制修订、owner/代数/租约及每动作20次/秒治理继续生效。

配置锁后的活动和历史证据使用当前锁读，避免 REPEATABLE READ 中竞争节点等锁后仍看到旧快照而创建第二事件。公共历史查询保持单个一致读事务。

## 管理 API 与中文页面

| 入口 | 语义 |
| --- | --- |
| GET `/accounts/{id}/cost-history` | 无出站，一致读取来源目标、近期/连续覆盖、最早成功、未知起点、缺口及尚未探测 |
| POST `/accounts/{id}/cost-range-preview` | 中文结构化 range/all 请求；无出站、不建任务或进度，展示实际期间/粒度/边界、整月扩展原因、延期、未到期及来源窗外 |
| POST `/accounts/{id}/cost-range-batches` | 202 + Location，可靠受理原父批次；各期间独立提交，父无 attempt；延期继续同一父事件 |

路径前缀为 `/admin/api/tencent`。读取复用成本查看动作，预览和受理复用已登记管理员重拉动作及 CSRF；所有响应 no-store，可信 UIN 关联真实入站审计。请求拒绝额外字段，指定范围最多十年。公开预览 hash 只绑定范围/配置/epoch/凭据安全修订，不含秘密或可用身份。

同键先定位原父批次再核请求意图，不按最新频率或日期重新解释；不同意图409。预览后配置/epoch/已存整月等改变实际范围时409并要求重新预览。命中完整月的日范围先扩大为整月，其他日期保留真实日；较早仅月可取时原月入队。受理保存完整非秘密执行模板，延期片和重试保留原 handler、配置及凭据修订、频率、策略、来源窗和实际期间，只在原模板上填日期边界。普通配置编辑不能扩大原请求或替换原输入。

页面增加历史卡、已探测缺口表、尚未探测说明、人工重探和结构化指定期间/全部实际可取历史预览；保留“立即近期复核”的原语义。任务详情披露请求范围、实际原始期间、延期/未到期/窗外及范围尚未全部完成。未知金额不写0，部分完成不宣称全范围成功。

窗口外人工旧月即使主空、辅助 Ready=1 且主辅总计0，仍不能独立证明当前可查，返回 `TENCENT_COST_ZERO_UNCONFIRMED` 并保旧。来源窗证据在受理时冻结；非空完整旧月仍可真实提交。日空继续不使用月 Ready 替代日证据；正负净零产品保持全集合。

## 0020 迁移、预检与恢复

唯一 head 为 `0020_tencent_history`，下接 `0019_tencent_daily`。新增 config.history_progress JSON、job.priority INT 与 `(config_id,status,priority,id)` 索引；每列中文 COMMENT，ORM/实际 schema 检查一致，不修改其他列、字符集、业务费用或约束。

业务环境执行另需授权。执行前只读核对 DATABASE()/VERSION()、当前 head0019、MySQL8.4/InnoDB、utf8mb4/utf8mb4_general_ci、UTC及REPEATABLE READ；保留 SHOW CREATE TABLE、配置/任务/期间/attempt一致备份和旧镜像。确认无正在执行的 worker/owner/active_job，再经统一迁移流程执行。检查已有job快照中的期间/父子/epoch及费用原值，不以本测试库替代各环境核实。

执行后核对 head0020、新列中文注释/默认值/空值、索引列序及ORM schema-check，比较原财务期间与回执未变，检查运行 readiness 与无出站历史读取。优先级只改变领取顺序。

MySQL DDL 非事务。失败时先核已提交列/索引及alembic_version，不盲目重复ADD或删表。保留全部业务事实，停止新采集并恢复兼容应用，或依据一致备份按已授权流程恢复。降级在任何DDL前检查历史进度/范围任务/优先级证据；跨0019/0018还提前核日配置、日任务/期间及batch证据，不允许先删0020列才被下一迁移拒绝。含证据优先应用回退，不能删除证据换取downgrade。仅空或明确可表达对象可在授权隔离库演练降升。
