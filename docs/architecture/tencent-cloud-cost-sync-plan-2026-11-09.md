# 腾讯云成本分析定时接入与余额实时查询方案

日期：2026-11-09；修订：2026-11-17。状态：Q1–Q6 已收到用户答复，业务范围已明确，待最终共同理解确认。独立成本看板保留日/周/月频率并自动复核近期账期；余额实时查询，不进入定时同步或历史余额表。仅现有管理员可用，整个腾讯云模块必须在组织初始化完成后开放；各云账号使用自身只读凭据。费用按完整期间事务覆盖，仅保留每个账期当前一份结果。尚未实施，真实账号只读联调待进行。答复及工程边界见 [设计审查记录](tencent-cloud-cost-design-review-2026-11-17.md)。

规格与跟踪：已按本轮 `to-spec` 整理 [实施规格](tencent-cloud-cost-and-balance-spec-2026-11-17.md)，发布 [Issue #15](https://github.com/mr-vilin/Evolution/issues/15)，标签为 `ready-for-agent`。用户已确认管理端 HTTP API＋实际任务执行、隔离 MySQL、腾讯云出站模拟及少量页面流程的测试边界；发布规格不替代此前最终共同理解及开始实现的待确认项。

## 1. 结论与范围

可以通过官方 API 定时拉取截图中的成本数据。首选 `DescribeCostExplorerSummary`，不需要抓取控制台页面。本文将用户所说的“成分分析”按截图理解为“成本分析”。[官方接口](https://cloud.tencent.com/document/api/555/103991)

成本业务当前先接入指定腾讯云账号、独立看板并首次回溯所有实际可取历史；公共账号和任务模型支持多账号，需要采集的每个“账号＋业务”独立配置。余额通过账号实时查询，不建立 balance 同步配置或任务；B 没有成本配置也可查自身余额，但同样受管理员和组织初始化门槛约束。成本每周日执行周同步，每月 3 日执行月同步。日/周补齐截至昨日的缺失日期，并每次复核当月截至昨日及上月；月模式新增上一个已到同步日的完整自然月，并每次复核最近两个已到同步日的完整账月。例如 12 月 3 日新增 11 月费用并复核 10、11 月，不采集 12 月 1–2 日。失败补齐遗漏日期或完整月份，更早历史保留手动重拉。

看板沿用截图的按月、产品、费用账单、总费用口径；调度频率与看板统计粒度是两个不同设置。部门/员工分摊、资源级明细、AI 分析、费用预测和腾讯云报告管理不纳入默认一期。全量回溯是需求目标，不代表官方接口已证明能返回账号创建以来的全部历史。

后续可能接入火山引擎及阿里云，本期所有成本表使用 `tencent_` 前缀，与其他厂商独立。费用只保存各期间的最新一份，不建立快照表、历史费用表或版本指针。同步完整范围内以腾讯云返回为准，覆盖金额、新增产品、删除源端已消失的产品；一次同步只覆盖本次范围，不删除其他月份。

本期实现成本分析与实时余额，云产品只预留扩展，未实现的处理器不可启用。账号、采集配置、逻辑任务和逐次尝试使用通用表，成本结果使用专用表。余额采用独立查询服务，只复用账号和后端凭据解析，不依赖成本配置或费用覆盖边界。余额主卡使用 `RealBalance`，现金、赠送、冻结、欠费和信用额度分开显示；进入页面或手动刷新时查询，显示本次查询时间，失败明确提示，旧值不冒充实时结果；不做自动轮询或余额历史分析。

用户已明确整个腾讯云模块必须在组织初始化完成后开放，包括账号配置、页面、余额查询、费用查看/导出、任务提交、定时调度、领取及费用提交。统一以 `dataset_state(id=1).initialization_status == 'complete'` 为事实源，保留现有会话和 CSRF 校验，不为云财务绕过初始化门槛。

本轮仅拉取远端 Git 状态、创建独立方案分支、核对官方资料和当前代码并修订设计文档；未读取腾讯云密钥、调用真实账单或余额 API、写业务库、修改运行代码或部署。API 可行性由官方文档支持，账号权限、归属和账单一致性仍待联调。

## 2. 接口选择及截图映射

| 用途 | 接口 | 使用方式 |
| --- | --- | --- |
| 主数据源 | `DescribeCostExplorerSummary` | 日/周模式采集日粒度；月模式采集完整自然月的产品汇总；统一形成产品月度看板 |
| 辅助对账 | `DescribeBillSummaryByProduct` | 按单月核对产品费用及产品编码；不能未经对齐就代替主接口 |
| 可选摊销视角 | `DescribeCostSummaryByProduct` | 消耗口径，只有明确需要时接入 |
| 余额实时查询 | `DescribeAccountBalance` | 由后端在查询时调用，按返回 UIN 核对账号；不创建同步任务 |

主接口使用 `billing.tencentcloudapi.com`、API 版本 `2018-07-09`，不要求 Region。截图与参数的映射如下。[接口参数与返回值](https://cloud.tencent.com/document/api/555/103991)

| 截图选项 | 请求参数 |
| --- | --- |
| 费用账单 | `BillType="1"` |
| 总费用（优惠后） | `FeeType="cost"` |
| 看板按月 | 月模式及历史完整月使用 `PeriodType="month"`；日/周增量使用 `day`，本地按自然月聚合 |
| 产品 | `Dimensions="business"`，`product` 表示子产品 |
| 时间范围 | `BeginTime` / `EndTime`，格式 `yyyy-mm-dd hh:mm:ss` |
| 全量数据 | `PageSize=100`，`PageNo` 从 1 开始，按 `Total` 翻页 |
| 获取产品字典 | `NeedConditionValue="1"` |

业务区间统一采用北京时间的半开区间 `[开始日 00:00:00, 截止边界 00:00:00)`。日/周的截止边界为执行日；月模式为执行月份的 1 日，且只有到每月 3 日才将上月纳入自动同步目标。API 请求转换为开始日零点至截止边界前一天 `23:59:59`。例如 2026-12-03 的月任务范围是 `[2026-11-01, 2026-12-01)`。查询按 API 允许的日期范围分片；日/周跨月增量按日采集再归入各自自然月；月模式按完整自然月分片。日/月粒度及边界须通过真实响应验证。数据库审计时间沿用项目 UTC 约定。正式调用由 SDK 生成签名，请求示例不应包含密钥。

接口返回表头、分类明细、总计和请求标识，足以支撑趋势图及产品×月份表。默认限频 20 次/秒；本系统初始并发设为 1、应用限速设为 1–2 次/秒，遇限流退避。[主接口](https://cloud.tencent.com/document/api/555/103991)

辅助费用接口只支持单月整月，能提供产品编码及支付构成；`Ready=0` 应进入稍后重试，官方建议等待约 10 分钟，不能发布为零费用。消费、退款、调账范围必须与主接口一致。[产品汇总费用接口](https://cloud.tencent.com/document/api/555/35761)

消耗账单体现摊销，与费用账单口径不同，不混入同一指标；只有业务确需摊销且已开通该能力时再增加。[消耗账单说明](https://cloud.tencent.com/document/product/555/37320)、[产品消耗汇总接口](https://cloud.tencent.com/document/api/555/41009)

余额接口的 `RealBalance` 是已确认的主卡指标，现金、赠送、冻结、欠费与信用额度有各自字段，金额单位为分；不能把信用额度和现金余额混称为同一个余额。官方将多个金额字段声明为 Float，适配时须从原始 JSON 数值保留十进制精度，不能先转二进制浮点再声称恢复原精度；后端精确转换为元，对外以明确币种和单位的十进制字符串返回。[获取账户余额](https://cloud.tencent.com/document/api/555/20253)

用户已确认各云账号使用自身只读凭据并查询自身费用和余额，本期不接入集团代付或统一凭据查成员账号。普通余额接口没有任意目标 UIN 入参；`account_uin` 与凭据引用不能代替归属验证，注册及轮换时验证身份，查询时核对返回 UIN。集团成员使用独立接口，未来如需支持，应重新设计财务归属与授权。[普通余额接口](https://cloud.tencent.com/document/api/555/20253)、[集团成员余额接口](https://cloud.tencent.com/document/api/555/132645)、[成本查询条件](https://cloud.tencent.com/document/product/555/19183)

## 3. 已发现的边界及处理

1. **更新延迟**：官方指南说明，费用口径日/月数据比费用明细晚 2–4 小时，当月不含未出账后付费；每月 2 日 12:00 后可查上月完整数据。同步成功只代表成功取得当前可用数据，不能标成最终结算锁定。[成本分析指南](https://cloud.tencent.com/document/product/555/60369)
2. **全量历史的接口限制**：指南给出控制台月级历史 12 个月、日级历史 6 个月；API 参数页未单独明确最大跨度及保留范围。首次回溯需查明账号最早有账单的月份和各接口实际可查边界。不能把最近 6 或 12 个月标为“全量完成”；超出主接口能力时评估官方账单下载/导出及历史账单导入，能否取回需另行验证。页面记录已覆盖范围和缺失月份，缺口未补齐时标“部分回溯”。[时间窗说明](https://cloud.tencent.com/document/product/555/60369)
3. **显示不等于全量**：控制台图表仅展示 Top10，其余合并；同步必须取得全量分页，数据库保留完整数据，Top10 仅为本地展示规则。[图表及表格说明](https://cloud.tencent.com/document/product/555/60369)
4. **产品标识**：`Detail` 未提供稳定产品码，`ConditionValue.Business` 提供 code/name 字典。仅在名称唯一且匹配明确时关联产品码；缺失或同名项保留原始名称、期间内行标识及未映射状态，不静默合并或丢弃。采用完整期间删除旧产品行并写入全部新行，不依赖跨次稳定行号或名称逐条匹配。[数据结构](https://cloud.tencent.com/document/api/555/19183)
5. **文档歧义**：数据结构把 `Name` 描述为时间，接口示例却使用产品名；按月示例也展示了日格式序列。需用真实响应确认列含义和粒度，并形成脱敏契约样本，不能照抄示例推算数据。[数据结构](https://cloud.tencent.com/document/api/555/19183)、[接口示例](https://cloud.tencent.com/document/api/555/103991)
6. **筛选不完全对应**：公开条件结构有产品、子产品、标签、项目、地域等，但未列资源 ID、分账单元；多值字符串和排除语法也不够明确。对应筛选暂不承诺；需要时先验证或改用其他官方明细/分账接口。顶层 `FeeType` 与 `Conditions.FeeType` 含义不同，不能混用。[查询条件结构](https://cloud.tencent.com/document/api/555/19183)
7. **汇总能力边界**：产品日/月汇总不能在本地还原项目、标签、地域交叉筛选或部门分摊。仅能获取月汇总的旧历史必须标识原始粒度，不能虚构每日金额。新增维度需新增受控查询数据集或获取明细，不能用各维度的独立汇总拼成多维明细。

腾讯云 worker 使用通用配置、逻辑任务及尝试历史表，独立实现云业务执行器，作为现有应用容器中的受监督进程；业务资格仍以组织初始化完成为前提。调度、领取及执行前检查初始化，任务冻结受理时的 `dataset_epoch`；提交事务按一致锁序锁定 DatasetState，复核 complete 且 epoch 未变化，再检查账号、配置及租约。重试不得重新绑定新 epoch。无可执行配置或初始化未完成时空闲，不将此状态当进程故障；凭据失败只影响对应任务，不反复重启应用。每配置单任务执行，跨配置独立，仍受接口和身份限流控制。

组织初始化的失败清理不扩大到 `tencent_*` 数据；恢复或初始化世代变化后保留云账号、配置、历史费用和任务证据，阻止旧任务提交，初始化重新完成后以新世代安排缺失期间。已完成系统目前没有日常重新初始化入口，此规则用于现有失败重来及受控恢复流程。页面收到 `INITIALIZATION_INCOMPLETE` 时刷新门禁并收起业务内容；余额请求也须在返回前复核本次 epoch，防止旧世代响应被展示为当前结果。

数据流：北京时间定时触发 → MySQL 任务记录 → 腾讯云全部分页采集 → 内存汇集完整期间并校验 → 短事务覆盖期间产品行、总计和进度 → 管理端读取本地唯一一份费用。分页尚未齐全时不删除现有费用；失败重试重新采集该期间，不持久化第二套费用版本。

## 5. 定时策略与一致性

本节为成本分析的频率及区间规则，执行时刻建议默认北京时间 13:30，并按账号＋采集业务分别配置；本次未创建实际自动任务。余额实时查询没有同步频率、下次执行或费用覆盖边界；未来云产品也不复用成本的历史回溯规则。

| 调度模式 | 触发日期 | 正常连续成功时新增范围及本轮复核 |
| --- | --- | --- |
| 按日 | 每天 | 11 月 9 日新增 11 月 8 日；复核 10 月全月及 11 月 1–8 日 |
| 按周 | 每周日 | 11 月 15 日新增 11 月 8–14 日；复核 10 月全月及 11 月 1–14 日 |
| 按月 | 每月 3 日 | 12 月 3 日新增 11 月，并复核 10、11 月两个到期完整账月 |

按月以完整自然月为采集、补漏及复核单位，与看板账期一致。12 月 1–2 日不在 12 月 3 日的月任务内，12 月费用在次年 1 月 3 日成为新增目标。除新增上月外，每次固定复核最近两个已到同步日的完整账月；每月 1–2 日尚未到上月同步日，复核目标也不能提前包含上月。更早失败月份继续补漏，不因只复核近期而放弃旧缺口。

- **首次历史回溯**：回溯所有实际可取历史，优先让近期范围可用，再按有界队列补齐更早期间。日/周截至昨日；月模式只包含已到同步日的完整自然月，每月 1–2 日最多到上上月。月模式保存真实月汇总；日/周保存真实日数据，旧历史仅有月汇总时保留原始粒度。同一自然月只存一份整月或若干不重叠日数据。无法取得的历史及未知的最早账期单独标记，不把近期可用说成全历史完成；旧账导入另行评估，不阻塞近期看板。
- **覆盖与缺口**：在该账号成本配置的受类型校验状态中分别保存已核验历史起点、缺失区间、近期实际覆盖及连续覆盖边界。日/周 `covered_until` 和月模式 `month_covered_until` 均不跨缺口推进，后者必须为月初；近期可用区间独立展示和用于生成后续目标，不因更早历史不可查而停滞。以已成功期间推导，不把最近尝试时间当覆盖起点，不修改其他配置进度。
- **失败与批次**：父任务汇总一个固定范围的批次，不领取执行租约；日/月期间子任务逐个采集并独立事务提交，配置租约仅由当前子任务持有。同一子任务跨日重试不改变范围。每个成功期间提交时更新自身回执及可推导覆盖；父任务仅在所有子期间成功后成功，部分成功和缺口明确展示，不把单个期间成功当作整批成功。
- **频率切换及停机**：保留既有期间及覆盖记录。切到月模式时，对已到同步日且缺少整月数据的自然月整月采集；通过后在同一事务中删除该月日数据及期间记录，写入唯一整月数据，不把部分日数据标记为完整月。切回日/周时保留已完整覆盖的历史月，仅对未覆盖日期采集日数据，不在月记录内插入重叠日记录。停机恢复时补建所有到期且未完成期间；月模式 1–2 日不提前拉取尚未到 3 日的上月。立即同步遵守所选模式的截止规则；月模式无待补账期时显示“已同步至上一个到期完整账月”，不提示已同步至昨日。
- **历史迟到与更正**：已确认自动复核近期费用：日/周每次重查当月截至昨日及上月；月模式每次复核最近两个到期完整账月，新增和复核重叠的期间只入队一次。已有月记录按整月重取，已有日记录按日重取并按自然月聚合，不能写重叠日/月金额。更早期间保留指定范围或全历史手动重拉，不承诺未重采的历史永远与源端一致。
- **重启恢复**：持久化应执行时间、任务状态和重试时间；调度去重与任务入队放在同一事务，避免进程重启丢任务。
- 去重范围：通用任务采用 `(config_id, idempotency_key)`；每个配置唯一绑定账号和业务。父批次以受理时的 `dataset_epoch`＋固定触发身份去重，期间子任务在父批次固定快照下增加粒度、起止及口径，父子分开命名。触发身份为计划执行点或手动提交的幂等身份；同事件在同世代重试定位原批次及配置快照，不读取最新配置重新生成范围。新世代补漏生成新身份，不能因旧任务占键而漏建。幂等键可采用该规范化身份的有界摘要。同配置任务串行，租约保存于配置，领取时任务记录隔离代数；提交同时核验 active_job_id、所有者、期限和代数，旧执行者不得覆盖新结果。
- 覆盖方式：先在事务外完成指定期间全部分页采集与校验，再在短事务中复核账号及业务启用状态、锁定成本配置和任务，删除该期间全部旧产品行、写入全部新产品行、更新期间总计、任务状态及该配置覆盖进度。各业务共用账号的启用检查采用共享行锁等协调方式，不以账号排他锁串行全部业务。按月替换整月，按日仅替换目标日；覆盖原日记录须已取得完整月数据。源端消失的旧产品一起移除，禁止仅 upsert 留脏行。失败回滚，保留同步前唯一数据；真实零费用可保留无产品行的期间记录。业务结果和对应配置进度必须同事务成功，不影响其他配置。
- 分页保护：检测重复页、提前空页、条数变化及总计不一致，出现异常重拉完整期间。公开接口未给出跨页一致性令牌，因此当月采集存在源数据变动风险，必要时再次读取总计复核；不宣称获得腾讯云的事务快照。
- 金额：Python 使用 Decimal，保留上游精度，展示时再格式化；负数退款正常保留。区分缺失、无权限、未准备、有效零值。按日/月和各产品求和与上游总计对照，差异保留原因与批次证据，不能静默修平。

## 6. 概念数据模型

本节是设计，不包含可执行 DDL，不声称已核实任何环境的实际数据库结构。

| 建议实体 | 主要内容 |
| --- | --- |
| `tencent_account` | 多账号身份、别名、凭据引用、账号总开关；不存某个业务的同步频率和进度 |
| `tencent_sync_config` | 账号＋业务唯一配置，独立频率、执行日、时刻、启停、下次执行、业务参数、业务进度及执行租约 |
| `tencent_sync_job` | 关联配置的执行任务、固定业务范围、状态、重试、租约代数及脱敏错误；不保存业务结果副本 |
| `tencent_sync_attempt` | 每个期间任务的逐次执行事实，含完整脱敏实际输入与处理器返回，重试不覆盖上一次记录 |
| `tencent_cost_period` | 每个日/月期间唯一一条：日期范围、币种、原始粒度、当前总计、产品数、最近成功同步时间 |
| `tencent_cost_item` | 期间 ID、期间内产品行标识、原始名称、可选产品码、映射状态、当前金额；重拉直接覆盖 |

字段、唯一键及虚拟示例详见 [详细表模型](tencent-cloud-cost-data-demo-2026-11-09.md)。本轮模型按四个通用基础表＋两个成本结果表整理，不设置 snapshot、head 或费用版本号。增加尝试历史是为保留历次执行事实，不保存另一份旧费用。成本处理器的真实最终返回定义为提交回执、期间 ID、条数及请求标识，并完整保存；内部账单分页不作为最终返回复制。配置有并发修订，任务冻结配置及初始化世代；成本进度只保存于对应配置。这是设计，不是已建成的数据库，物理精度与运行预算仍须实现及联调验证。

期间唯一键为 `(account_id, grain, period_start)`，产品行唯一键为 `(period_id, row_key)`。唯一键本身不能禁止日/月范围重叠，须在该账号成本配置锁保护下额外检查；期间账号必须与最近成功任务的配置账号相同，任务业务必须是 cost_analysis。重复同步复用同一期间，不新增历史副本。看板按账号查询期间及产品表，再按自然月聚合；产品名称不作为永久业务主键。正常同步仅保留 RequestId、行数、状态等运行元信息，不留原始响应副本；联调契约样本与业务库隔离。多币种不得直接合计，币种及金额单位须联调确认。

金额拟用有符号 `DECIMAL(24,8)`，以真实响应精度验证后定稿，超精度不得静默截断。新增表按项目 MySQL 8.4、InnoDB、`utf8mb4_general_ci` 设计，稳定 ID 按项目约定使用二进制比较。表和每个字段均添加中文注释；不改现有表字符集、外键或组织业务字段。实施前核验目标环境版本、schema、会话配置，提供 Alembic 迁移、预检、验证、备份恢复及回退说明。迁移与真实同步另按授权范围执行。

## 7. 权限、配置与页面

腾讯云侧每个独立账号使用自身的只读子用户或角色，本期基础动作包括 `finance:DescribeCostExplorerSummary` 和 `finance:DescribeAccountBalance`；确需辅助对账时再添加 `finance:DescribeBillSummaryByProduct` 等实际调用的只读动作。CAM 服务前缀是 `finance`，这三个动作均为操作级、资源为 `*`，官方列明不支持 IP 限制，不应套用资源级授权或假设 IP 条件有效。每个账号分别验证权限及凭据归属，本期不要求集团财务授权，也不通过传入其他 UIN 切换账号。[CAM 费用中心权限表](https://cloud.tencent.com/document/product/598/92835)

凭据仅在后端以部署 secret 或已有安全配置渠道注入，数据库保存引用，不在浏览器、日志、响应证据或普通配置行中存放可用密钥。上线前验证轮换、权限撤销后的错误提示及恢复路径。

管理端提供“云成本分析”页面：月份范围、账号、月度趋势、产品月度表、总额、数据口径、最近成功同步时间及任务状态。月模式当前月显示“待下月 3 日同步”，金额为空而不是零；日/周模式当前月累计明确标记未完整出账。过期、缺口和同步失败可见。已确认仅现有管理员白名单可用，普通组织目录查看者无财务访问资格；各已声明动作分别检查，后续新增权限不因历史通配符自动授予。

账号页维护账号别名、凭据引用和总开关；业务同步配置页仅列需要定时采集的业务，按“账号、业务、频率、执行时刻、启停、最近成功、下次执行”逐行展示。余额从账号进入实时查询，不在同步列表出现，也没有“立即同步余额”动作。全部配置使用中文结构化表单，禁止要求用户编辑 JSON。成本周模式固定周日、月模式固定每月 3 日，并提供费用截止说明及历史补拉。成本成功显示费用覆盖状态，余额显示本次查询成功时间和实际返回的金额口径，不套用费用覆盖提示。账号停用阻止新查询、所属业务领取及在途新结果发布；单采集业务停用不影响同账号其他能力。

选择“按月”时，单独展示说明文案：

> 每月 3 日按设定时间同步上一个完整自然月，并复核最近两个已到同步日的完整账月。例如 12 月 3 日新增 11 月并复核 10、11 月，不包含 12 月费用。首次执行回溯所有实际可取的到期历史账月，缺失月份会明确显示；失败后自动补漏。每月 1–2 日立即同步也不提前采集上月。更早历史如有补记或调账，可手动重拉。

费用看板读取本地当前费用，不提供版本选择或费用历史对比，不随每次浏览调用腾讯云；成本“立即同步”可靠受理后返回任务编号及查询入口。余额进入页面或手动刷新时访问腾讯云，独立设置超时、限流，显示本次查询时间；失败明确提示，旧值不冒充实时余额，不保存余额历史。图表可展示 Top10 加其他，表格和导出包含完整产品。同比仅在上年同期覆盖完整且口径一致时计算；完整月环比可算，分母为零或缺失显示“—”，当月累计不包装成完整月降幅。

## 8. 分阶段实施与验收

1. **只读联调**：使用指定账号读取一个已出完整账月份及当月截至昨日的数据，并探测最早历史可查边界。记录脱敏请求/响应，核验权限、时间边界、日粒度过滤、币种、产品码映射、退款调账及分页。已出账月对照同一时间、账号及筛选条件的控制台导出；不能把截图中的历史金额当成实时验收值。
2. **采集与持久化**：实现腾讯云通用账号、按采集业务配置的调度/重试和成本处理器。验证账号及配置隔离、重复账号＋业务被拒绝、同配置任务互斥、跨配置限流及逐次尝试历史，再验证费用重复同步只留一份、消失产品删除、真实零账单、失败回滚、旧任务隔离及日/月不重叠。使用真实隔离 MySQL 验证事务与迁移；余额查询不创建同步配置或任务，云产品预留配置不等于真实接入成功。
3. **管理端展示**：按确认的角色和业务范围实现页面与结构化配置。覆盖权限拒绝、空数据、未完整出账、同步失败时展示原数据、失败重试、金额精度、负数及全量导出。
4. **发布与真实验收**：迁移获得对应授权并完成备份恢复演练后，仅在用户明确要求部署时使用 `deploy/release.py`，只说“部署”时目标为本地；通过真实账号完成一次拉取和一次定时触发，核验总计及全部产品。余额另验实际账号归属、金额单位、查询时间和超时/权限失败。远端测试和正式环境须单独明确指定。

完成标准：同账号、同口径、同时间范围的全部产品和金额与腾讯云本次完整响应一致；高精度差异可解释并留证；分页没有遗漏、已消失产品无残留；重启、重试及连续两次同步只有一份费用；源错误时仍能查看同步前数据；其他月份不被误删；组织同步与登录流程不受影响。增加周日、每月 3 日、跨年/月末、执行当天排除、跨日重试、失败补拉、频率切换、全量缺口标识及历史月/日数据不重复计数的验收案例。以已采集日期后补费用验证近期复核确实更新旧值，以历史不可查询验证缺口不阻塞近期入库；初始化未完成时页面、查询、人工/自动任务均不可用，恢复导致 epoch 改变后旧尝试不得提交，新世代可生成补漏任务，普通组织发布保留 epoch 时合法任务不被误阻断。

## 9. 已确认事项与剩余问题

已确认：本期成本看板与实时余额，云产品只预留；日/周/月及周日、每月 3 日规则；按既定范围自动复核近期历史；全部实际可取历史回溯且缺口可见，近期先用；仅现有管理员，组织初始化完成后整个腾讯云模块才开放；各账号独立凭据和数据归属。所有表用 `tencent_` 前缀，费用按期间单份覆盖，不存余额历史。上述不再重复询问。

待落地核实：

1. **历史完整性**：真实账号最早账期、API 可查范围，以及缺口能否通过官方历史账单或导出补齐。完整历史不可获取时必须反馈缺失范围，不能擅自缩为近 6 个月。
2. **联调契约**：核实真实账号、余额单位/币种及小数精度、费用粒度和零账单判定，补充脱敏契约样本；这些事实不能用用户对方案的答复代替。
3. **运行参数**：执行时刻仍建议北京时间 13:30，可配置；执行预算、重试退避、队列限制和日志/尝试历史留存须在实现时登记项目值，不沿用组织 worker 的固定参数冒充已验证的云业务预算，也不因本轮设计自动开启清理。

真实联调需要已配置的只读身份；用户无需在聊天中粘贴密钥。公开资料不足以证明账号现有权限、所有控制台筛选能力或历史数据可查询范围。本次仍为方案修订，未创建实际同步任务。
