# 腾讯云通用同步模型与成本覆盖示例

日期：2026-11-09；修订：2026-11-17。状态：Q1–Q6 已答复，按四个腾讯云通用基础表、两个成本结果表整理模型，补齐逐次尝试、配置修订、批次/期间及初始化世代边界。余额实时查询，不建同步任务或历史余额表；费用仍单份覆盖。仅现有管理员在组织初始化完成后可用，各云账号使用自身凭据。尚未建表、迁移、真实同步或部署。本文账号、ID、金额和执行记录均为虚拟数据。规则见 [接入方案](tencent-cloud-cost-sync-plan-2026-11-09.md)，答复及边界见 [设计审查记录](tencent-cloud-cost-design-review-2026-11-17.md)。

## 1. 设计结论

- 所有表使用 `tencent_` 前缀。后续火山引擎、阿里云独立接入，不混入腾讯云费用表；本次不预建其他云的表。
- 账号、业务同步配置和执行任务分开：同一腾讯云账号只建一次，每个需要采集的“账号＋业务”有独立配置、进度、启停及运行记录。支持 A 账号成本每月、未来云产品独立采集；余额实时查询不创建同步配置和任务。
- 当前成本先接入指定账号；公共模型不限制为单账号。余额查询复用账号及后端凭据解析，不依赖成本配置；B 可以只登记账号并查询余额。云产品仍仅预留采集处理器扩展，不代表已经实现。
- 费用只保留一份当前值。不设 snapshot、head、费用版本号或历史金额表；同步任务仅记录运行情况，不复制产品费用。
- 按月时一个账月一条期间记录，每个源产品一条费用记录。完整重拉后覆盖整月产品集合，包括删除不再返回的旧产品。
- “一份”指每个历史账期一份最新金额，不是只保留最新月份。同步 11 月不能删除 9 月、10 月。
- 每月 3 日新增上一个完整自然月，并复核最近两个已到同步日的完整账月：2026-12-03 新增 11 月、复核 10 和 11 月，不含 12 月 1–2 日。日/周每次复核当月截至昨日及上月；漏跑后补齐缺失期间。
- 覆盖保证本次已成功采集范围内与腾讯云本次完整响应一致。初次历史可查询范围、账单延迟及后续历史调账仍须真实验证，不把单次覆盖描述为永久实时一致。
- 旧账不可取时缺口可见，允许近期数据先使用；缺口、近期覆盖和连续覆盖分别表达，不因早期缺口阻塞新的费用采集。
- 整个腾讯云模块要求组织初始化完成；失败重来及恢复不清除腾讯云数据，旧世代任务不得提交或重新绑定新世代。

## 2. 六表模型：四个通用表、两个成本表

目标为项目约定 MySQL 8.4 / InnoDB / utf8mb4_general_ci，稳定标识按 utf8mb4_bin 比较；本次未核验运行实例。以下是设计字段，不是可执行 DDL。

六表统一包含 `id INT` 自增主键、UTC `create_time / update_time DATETIME`。关联 ID 统一 INT，由应用保证完整性，不新增物理外键。费用日期按北京时间解释，存 DATE；运行及审计时刻存 UTC DATETIME。真实迁移的每个字段和表须有中文注释，并提供预检、验证和恢复说明。以下是实施模型草案，真实响应精度、目标 MySQL 结构与运行参数尚须核验。

### tencent_account：腾讯云账号

| 核心字段 | 拟定类型 | 用途 |
| --- | --- | --- |
| account_uin / alias | VARCHAR(64) / VARCHAR(100) | 腾讯云账号及中文别名，UIN 不转整数 |
| credential_ref | VARCHAR(191) | 部署凭据引用，不保存密钥 |
| is_enabled | TINYINT UNSIGNED | 账号总开关，1 启用、0 停用 |

唯一键 `account_uin`。同一账号的多个业务共享该账号身份和凭据引用，不重复建账号；账号表不放同步频率、成本口径、成本覆盖边界或某个业务的成功时间。账号 UIN 为不可重新绑定的身份，不能修改 UIN 将原业务数据变成另一个账号的数据。

凭据引用须经后端受控解析，不能把管理员可填的任意文件路径或环境变量名直接作为可读取的秘密。已确认各账号使用自身只读凭据和归属，不接入集团代付；注册与轮换时验证绑定，余额查询每次核对上游返回 UIN。普通接口不支持传入任意 UIN 切换账号，不能把一个账号的凭据与另一个账号的 UIN 拼接使用。

### tencent_sync_config：账号＋业务的同步配置与状态

| 核心字段 | 拟定类型 | 用途 |
| --- | --- | --- |
| account_id | INT | 关联 tencent_account |
| business_type | VARCHAR(32) | cost_analysis 成本分析；cloud_product 为未来采集扩展，未接入不可启用；不含余额查询 |
| is_enabled | TINYINT UNSIGNED | 该账号该业务的独立开关 |
| config_revision | INT UNSIGNED | 配置并发修订号；编辑时比较，冲突不覆盖；不是费用版本 |
| frequency / run_time / timezone | VARCHAR(16) / TIME / VARCHAR(64) | daily / weekly / monthly；执行时刻；Asia/Shanghai |
| day_of_week / day_of_month | 可空 TINYINT UNSIGNED | 周几 1–7 或每月几号 1–31；daily 两者为空，weekly 仅周字段有值，monthly 仅月字段有值 |
| next_run_at | 可空 DATETIME | 该配置下次 UTC 应执行时间 |
| settings_json | JSON | 各业务经校验的专用参数，不放凭据和业务结果 |
| state_json | JSON | 各业务独立的同步进度和覆盖状态，不存费用、余额、产品清单等结果 |
| execution_policy | JSON | 受类型校验的重试、单次/轮次预算、排队和补跑限制；前端使用结构化表单 |
| last_success_at | 可空 DATETIME | 该账号该业务最近成功时间 |
| active_job_id | 可空 INT | 当前执行任务；原子领取以保证同配置单任务执行 |
| lease_owner / lease_until / lease_generation | 可空 VARCHAR(191) / DATETIME / INT | 配置级租约及防旧执行者覆盖的隔离代数，不是业务数据版本 |

唯一键 `(account_id, business_type)`；索引 `(is_enabled, next_run_at)`。当前每个账号的每类业务只有一套配置；不同账号或不同业务独立调度。账号和业务绑定不可编辑，配置停用后保留其历史任务和业务数据，避免悬空关联。

成本的周模式固定周日（7）、月模式固定 3 日，由成本处理器校验。`settings_json` 固定费用账单 / 总费用 / 产品全量口径及核验后的币种，并声明已确认的近期复核策略：日/周当月截至昨日及上月，月模式最近两个到期完整账月。`state_json` 含已核验历史起点、回溯目标、连续边界、近期可用区间、回溯状态及缺失区间，按日期严格校验并事务更新；连续边界不跨缺口，近期采集也不被更早不可取历史阻塞。新采集配置默认关闭，启用前校验注册处理器、参数及运行策略。

JSON 仅为内部存储：每个已接入采集业务须有明确的 Pydantic 参数和状态模型，未知业务码拒绝启用。前端提供中文结构化表单，不要求用户编辑 JSON。余额查询不进入本表，没有同步频率、费用账期或“截至昨日”的覆盖状态；云产品也不套用费用历史回溯。

初始化 complete、账号总开关和业务开关均启用才可生成自动任务及领取。配置开关/账号停用与提交按统一锁顺序协调，提交前复核，已停用不发布在途新结果。编辑使用 `config_revision`，仅影响后续新轮次；历史任务的业务目标和快照固定，重试仍检查当前开关、授权和初始化世代。

### tencent_sync_job：通用同步执行任务

| 核心字段 | 拟定类型 | 用途 |
| --- | --- | --- |
| config_id / parent_job_id | INT / 可空 INT | 关联同步配置及批次父任务；账号和业务从不可变配置绑定取得 |
| job_role | VARCHAR(16) | batch：仅汇总的父记录；period：可执行的单日/整月期间任务 |
| job_type / trigger_type | VARCHAR(24) | backfill / incremental / refresh；定时或手动，能力由对应业务处理器校验 |
| scope_json | JSON | 入队时固定的执行范围及有效业务参数；成本含起止日期和 day / month；余额不创建本类任务 |
| config_snapshot | JSON | 当轮配置修订、处理器版本、账号/业务、有效参数、运行策略及可信发起身份；不含秘密值 |
| dataset_epoch | CHAR(36) | 受理任务时固定的组织初始化世代；执行、提交及重试必须保持一致，不是费用版本 |
| idempotency_key | VARCHAR(191) | 父批次按固定世代与触发身份生成，期间子任务另含固定期间及口径；同次重试复用，主动重拉使用新提交身份 |
| status / attempt_count | VARCHAR(24) / INT UNSIGNED | 待执行、运行、待重试、成功、失败或阻断；父批次另可为部分失败；次数为汇总值 |
| scheduled_at / retry_at | DATETIME / 可空 DATETIME | 应执行和重试时刻 |
| deadline_at / source_job_id | DATETIME / 可空 INT | 有界执行截止；人工重跑关联原逻辑任务，新建任务而非覆写历史 |
| lease_generation | 可空 INT | 领取时取得的配置租约代数，提交时与 config 比对 |
| started_at / finished_at | 可空 DATETIME | 开始及结束时刻 |
| row_count / request_ids_json | INT UNSIGNED / JSON | 本次结果行数及分页请求标识，不保存费用、余额或产品结果副本 |
| error_summary | 可空 VARCHAR(1000) | 脱敏错误摘要，不保存密钥、原始响应及整批账单 |

唯一键 `(config_id, idempotency_key)`；索引 `(status, retry_at)`、`(config_id, scheduled_at)`、`(parent_job_id, status)`。每条配置同一时刻只执行一个期间子任务，重试等待也保留该逻辑任务的串行资格；父批次不领取租约。其他子任务有界排队，近期新期间优先于较早历史回溯。新增与近期复核重叠期间归一化后只建一个子任务。A 的成本任务不占用 B 的配置，也不阻塞独立余额查询，调用仍遵守接口及身份限流。

父批次和期间子任务使用不同的幂等命名空间，完整身份超过键长度时保存规范化摘要。父批次键按 `dataset_epoch`＋计划执行点或手动提交身份确定；期间键使用原批次固定快照中的粒度、起止及口径。同一事件在同世代重新受理时先定位原批次，不因当前配置已编辑而重建；配置修订保存在快照中，不能用最新修订改变原事件身份。真正的新触发事件或新世代补漏才使用新身份。新世代必须隔离旧 active_job_id 及租约，保留旧任务证据，不复用旧任务绑定；费用期间唯一键仍不含 epoch，继续保留各账期当前一份结果。

领取期间任务须原子设置 config 的 active_job_id 和租约。执行和提交均要求 DatasetState 初始化 complete 且 epoch 等于任务固定值；提交事务先按统一锁序锁定该状态行，再核验账号、配置、当前期间任务、租约所有者、期限及代数。不同配置可对状态行采用共享锁，恢复/初始化状态变更以排他锁协调，不用全局排他锁串行所有云任务。旧世代或旧租约不能提交，新世代不得重新绑定旧任务；恢复后保留证据并隔离旧活动任务，按新世代生成所需期间。处理器校验范围、口径和账号，期间结果、提交回执、尝试结果、任务状态及成本进度同事务成功。

每个期间独立提交，父批次状态由子任务推导；全部成功才标成功，部分成功、失败或阻断分别可见。空业务范围为明确的无待同步结果，不生成虚假的期间费用；接口受理与任务最终成功分开。

注册表把 business_type 映射到受控采集处理器，负责参数校验、范围计算、采集、校验及结果写入；通用调度器仅负责领取、租约、重试和任务状态。云产品未接入处理器前，预留码不代表可以执行；余额始终走查询服务，不注册为定时同步处理器。

### 账号与配置示例

`tencent_account` 只有 A、B 两条账号记录。下列为 `tencent_sync_config` 的两条示意配置，未创建实际任务，云产品一行只说明未来扩展：

| 配置 ID | account_id / 账号 | business_type / 业务 | frequency | 执行日 |
| --- | --- | --- | --- | --- |
| 101 | 1 / A | cost_analysis / 成本分析 | monthly | 每月 3 日 |
| 102 | 1 / A | cloud_product / 云产品 | weekly | 每周日（未来示例，当前不可启用） |

A 的成本任务通过 config_id=101 追踪，成本失败只影响其成本任务及状态。A、B 的余额查询使用各自账号，不创建配置 103/104，不更新任何同步成功时间或费用进度；B 没有成本配置也可查询余额。采集配置可以查看最近成功和下次执行；余额显示当次查询时间。账号总停用同时阻止新查询和所属采集任务，停用 A 成本配置不自动禁止 A 的余额查询。

### tencent_cost_period：唯一业务账期

| 核心字段 | 拟定类型 | 用途 |
| --- | --- | --- |
| account_id | INT | 关联通用 tencent_account，所属腾讯云账号 |
| grain | VARCHAR(8) | month：完整自然月；day：完整自然日 |
| period_start / period_end | DATE | 半开区间；11 月为 `[2026-11-01,2026-12-01)` |
| currency / source_kind | CHAR(3) / VARCHAR(24) | 币种及 api_month / api_day / historical_import 来源 |
| total_amount | DECIMAL(24,8) | 与源总计校验一致的当前产品合计，可为负数 |
| item_count | INT UNSIGNED | 当前产品行数，零费用期间允许为 0 |
| last_job_id / last_attempt_id / synced_at | INT / INT / DATETIME | 最近成功的期间任务、执行尝试及 UTC 时间；必须属于同账号成本配置，支持提交后故障核实 |

唯一键 `(account_id, grain, period_start)`；范围查询索引 `(account_id, period_start)`。期间 ID 是稳定业务容器 ID，重复拉取同一日/月复用它，不因重拉插入新期间。只有完整成功期间落表；失败记录在 tencent_sync_job，缺口记录在对应成本配置的 state_json。未成功日期没有期间记录，成功零费用有总额为零的期间记录。不同账号的成本分别存储、筛选和对账。

### tencent_cost_item：期间内的当前产品金额

| 核心字段 | 拟定类型 | 用途 |
| --- | --- | --- |
| period_id | INT | 所属期间 |
| row_key | VARCHAR(191) | 本次完整响应归一化后的产品行标识，仅在期间内使用 |
| business_code | 可空 VARCHAR(191) | 产品维度的官方 BusinessCode，可靠匹配后填写；不与子产品 ProductCode 混用 |
| product_name / mapping_status | VARCHAR(255) / VARCHAR(24) | 原始名称及 mapped / unmapped / ambiguous 状态 |
| amount | DECIMAL(24,8) | 该期间该产品的当前总费用，有符号精确小数 |

唯一键 `(period_id, row_key)`；可按查询计划增加 `(period_id, business_code)` 索引。完整覆盖时删除全部旧产品行并重插，不用行号或中文名跨次匹配。产品码可靠时用于跨月展示，未映射和同名歧义行分别显示，不丢弃或静默合并。保留 `product_name` 作为原始展示名称，不据此推定稳定产品身份。

精度须以真实响应验证，超精度报错，不静默截断；Python 使用 Decimal，展示才保留两位。币种不同禁止合计。产品行的日期、币种和同步任务从期间继承。

### tencent_sync_attempt：逐次尝试历史

本轮模型纳入，尚未建表。`attempt_count` 只能统计次数，不能替代历次输入、返回及失败事实。每个可执行期间任务保留一个逻辑任务 ID，每次重试另增尝试，不覆盖之前记录；纯汇总父批次没有处理器调用，不伪造执行尝试。

| 字段或字段组 | 拟定类型 | 用途 |
| --- | --- | --- |
| job_id / attempt_no | INT / INT UNSIGNED | 逻辑任务及从 1 递增的尝试号，同轮重试不换 job_id |
| config_revision / handler_version | INT UNSIGNED / VARCHAR(32) | 当轮配置修订及处理器契约版本，不是费用版本 |
| dataset_epoch | CHAR(36) | 实际尝试使用的初始化世代，必须与逻辑任务一致 |
| execution_input | JSON | 默认值、日期解析完成后的完整脱敏实际业务输入；先可靠保存再调用处理器 |
| execution_output | JSON | 完整脱敏实际返回及返回形态、保存状态；未返回或未知不能伪造空成功结果 |
| status / reason_code | VARCHAR(24) / 可空 VARCHAR(64) | 当次状态、失败或跳过原因，与任务最终状态分开 |
| executor_id / lease_generation | 可空 VARCHAR(191) / 可空 INT | 当次执行者及取得的隔离代数 |
| started_at / finished_at / duration_ms | 可空 DATETIME / 可空 DATETIME / 可空 BIGINT UNSIGNED | 实际起止观测及单调时钟耗时；没有证据时为空 |
| error_code / error_summary | 可空 VARCHAR(64) / 可空 VARCHAR(1000) | 当次脱敏错误，不保存可用凭据 |
| request_ids_json | JSON | 关联本次外部请求，不能用请求 ID 替代完整执行输入输出 |

唯一键 `(job_id, attempt_no)`，任务查询索引 `(job_id, started_at)`。输入输出使用带模型版本、捕获状态、返回形态的封装；超过项目内联预算时使用可按当前权限取回的完整受控引用，摘要与日志链接不能替代实际内容。容量和留存仍待定，不据此新增对象存储或其他基础设施。

费用采集处理器的最终业务返回为提交回执、成功期间 ID、条数及请求标识，逐次完整保存真实返回；内部分页响应不是最终返回，不复制为旧费用版本。成功回执和正常返回内容在费用事务中可靠记录，失败尝试独立于费用回滚；已确认提交但返回保存有缺口时核对原任务/尝试并修复历史，不能仅为补记录重放业务。运行策略和留存项目值在实现时登记，不因本轮修订开启真实清理。

## 3. 完整期间事务覆盖

以重拉 11 月为例：

1. 固定账号、口径和 `[11-01,12-01)`，在事务外获取所有分页、字典及源总计，放入本次内存工作集。
2. 校验无重复页、漏页、提前空页和条数变动，金额可解析，产品合计与源总计一致。无法确定完整时失败退出，不动费用表。
3. 开启短事务，按统一锁序锁定 DatasetState，复核初始化 complete 且 epoch 与任务固定值一致；再检查账号开关、配置、当前期间任务、租约和代数。只读核对即将替换的期间及行数。对公共状态和账号可用共享行锁，避免全局串行不同配置。
4. 存在 11 月月期间则复用 ID，删除其全部旧产品行，插入全部新产品行，更新总额、产品数和同步时间。若原来是日存储，在同一事务删除本月全部日产品行和日期间，写入唯一完整月数据。
5. 在该事务保存本次提交回执、完整正常返回、成功尝试及期间任务状态，更新对应成本配置的覆盖和缺口，一起提交。失败则回滚并独立记录失败尝试，不修改其他配置。父批次由子期间状态汇总，不把单期间成功当作整批成功。

正常流程不保存旧费用副本，不长期落地原始账单响应；内存工作集不供看板读取。必要的数据库备份属于部署恢复手段，不是费用版本功能。

只有已核验账期可查且数据就绪、分页确认完整、源总计为零且接口契约允许空产品集时，才用零覆盖旧非零金额。主接口没有通用就绪标志，不能从一个空页推断；必要时结合口径一致的辅助对账，`Ready=0` 时重试，仍无法确认则保留旧值并报告未确认。空页、无权限、未准备、解析失败不能触发清空。

看板一次响应中的总额、产品表和日期覆盖状态在同一个一致性读事务中查询；提交前看到原完整数据，提交后看到新完整数据，不看到删除和插入之间的中间态。

## 4. 日、周、月只存一份

| 场景 | 存储与查询 |
| --- | --- |
| 月同步 | 每月一个 period、产品各一行；每月 3 日新增上月并复核最近两个到期完整账月，缺失旧月份另补齐 |
| 日/周同步 | 完整自然日各存一个 period；每次复核当月截至昨日及上月，看板按月求和，不另存月聚合金额 |
| 日/周切到月 | 完整月拉取校验通过后，事务内删除该月日数据并写入月数据 |
| 月切到日/周 | 保留历史完整月，已覆盖日期不再写日记录；未覆盖日期继续按日采集 |
| 日范围补拉遇到月记录 | 明确展示按整月补拉的实际范围，重取并覆盖整月，不叠加几天金额 |

同一账号同一自然月只允许月记录或日记录二选一。唯一键不能防止日/月相交，应用须在该账号的成本配置锁内检查重叠期间。只有月汇总的历史不能平均拆为虚构日数据。日模式当前月覆盖不全时，显示累计截止日和缺口，不显示为完整月。

所有页面与接口仅向已完成组织初始化的现有管理员开放。账号页维护身份及凭据引用，余额主卡使用 `RealBalance`，现金、赠送、冻结、欠费和信用额度分别展示；进入页面或手动刷新直接查询，显示查询时间，失败明确提示，旧值不冒充实时结果，不保存余额历史。配置页仅列采集业务。成本显示覆盖和缺口，余额不显示费用覆盖边界、不进入任何同步结果表。未来云产品结果单独设计。

“完整覆盖”在一期指已确认的费用账单 / 总费用 / 产品口径下，本次成功范围的全分页、全产品当前金额，不代表全部历史已经取回。近期复核之外的历史调账可指定账期或全历史手动重拉；实际可取边界如实显示，缺口不阻塞近期使用。月任务的自动范围按用户已确认的最近两个到期完整账月复核，不扩展为每次重取全历史。

## 7. 验证与实施边界

实施前核实目标 MySQL 版本、schema、字符集及会话配置，提供迁移预检和恢复说明；真实写入另按授权执行。联调验证 API 全分页、维度、单位、精度、历史边界及对账。本次只修订设计。

初始化门槛按 Q5 执行，使用现有 DatasetState；不得把独立云表加入组织失败重来的清理清单。覆盖初始化未完成时的页面、查询、手动/自动任务拒绝，初始化/恢复世代变化后的旧任务拒绝，以及新世代补漏；普通组织发布不改变 epoch，不因此阻断合法云任务。余额返回前复核同一门槛，避免恢复前的在途查询在新世代页面中展示。

实施验收包括：不同账号及采集业务配置独立保存，重复账号＋业务被拒绝；余额查询不创建同步配置或任务、不修改成本覆盖进度；单业务停用不影响同账号其他能力；账号总停用阻止新查询、所属业务领取和在途新结果发布；成本失败不串改其他配置；同配置任务互斥、跨配置允许并行且正确限流；不同账号不串数据；每次重试有独立、完整脱敏输入输出事实；重复同步一份费用；消失产品无残留；有效零账单可清除旧非零金额；空页或失败不误清空；事务失败完整回滚；日/月无重复期间；过期任务不能写入；查询无中间态；不误删其他月份；缺口与未同步状态可见。余额另验证返回 UIN、分/元转换、查询时间和失败语义；云产品处理器未接入前不宣称已完成真实采集。使用真实隔离 MySQL 验证，不用文档示例代替。
