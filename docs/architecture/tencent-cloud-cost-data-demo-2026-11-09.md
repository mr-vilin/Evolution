# 腾讯云通用同步模型与成本覆盖示例

日期：2026-11-09。状态：按最新要求调整为三个腾讯云通用基础表、两个成本业务表，支持多账号按业务分别配置同步；费用仍单份覆盖。尚未建表、迁移、真实同步或部署。本文账号、ID、金额和执行记录均为虚拟数据，未来日期仅用于演示。规则见 [接入方案](tencent-cloud-cost-sync-plan-2026-11-09.md)。此前账号绑定成本调度及费用版本演示均已被本设计取代。

## 1. 设计结论

- 所有表使用 `tencent_` 前缀。后续火山引擎、阿里云独立接入，不混入腾讯云费用表；本次不预建其他云的表。
- 账号、业务同步配置和执行任务分开：同一腾讯云账号只建一次，每个“账号＋业务”有独立配置、进度、启停及运行记录。支持 A 账号成本每月、云产品每周、余额每天，B 账号仅余额每天。
- 当前成本先接入指定账号；公共模型不再限制为单账号，也不为其他业务要求先开通成本分析。余额和云产品业务在模型中预留处理器入口，接口及业务结果表后续确认，不代表已经实现。
- 费用只保留一份当前值。不设 snapshot、head、费用版本号或历史金额表；同步任务仅记录运行情况，不复制产品费用。
- 按月时一个账月一条期间记录，每个源产品一条费用记录。完整重拉后覆盖整月产品集合，包括删除不再返回的旧产品。
- “一份”指每个历史账期一份最新金额，不是只保留最新月份。同步 11 月不能删除 9 月、10 月。
- 每月 3 日拉取上一个完整自然月：2026-12-03 → 2026-11-01 至 2026-11-30，不含 12 月 1–2 日。漏跑后补齐遗漏月份。
- 覆盖保证本次已成功采集范围内与腾讯云本次完整响应一致。初次历史可查询范围、账单延迟及后续历史调账仍须真实验证，不把单次覆盖描述为永久实时一致。

## 2. 五表模型：三个通用表、两个成本表

目标为项目约定 MySQL 8.4 / InnoDB / utf8mb4_general_ci，稳定标识按 utf8mb4_bin 比较；本次未核验运行实例。以下是设计字段，不是可执行 DDL。

五表统一包含 `id INT` 自增主键、UTC `create_time / update_time DATETIME`。关联 ID 统一 INT，由应用保证完整性，不新增物理外键。费用日期按北京时间解释，存 DATE；运行及审计时刻存 UTC DATETIME。真实迁移的每个字段和表须有中文注释，并提供预检、验证和恢复说明。

### tencent_account：腾讯云账号

| 核心字段 | 拟定类型 | 用途 |
| --- | --- | --- |
| account_uin / alias | VARCHAR(64) / VARCHAR(100) | 腾讯云账号及中文别名，UIN 不转整数 |
| credential_ref | VARCHAR(191) | 部署凭据引用，不保存密钥 |
| is_enabled | TINYINT UNSIGNED | 账号总开关，1 启用、0 停用 |

唯一键 `account_uin`。同一账号的多个业务共享该账号身份和凭据引用，不重复建账号；账号表不放同步频率、成本口径、成本覆盖边界或某个业务的成功时间。账号 UIN 为不可重新绑定的身份，不能修改 UIN 将原业务数据变成另一个账号的数据。

### tencent_sync_config：账号＋业务的同步配置与状态

| 核心字段 | 拟定类型 | 用途 |
| --- | --- | --- |
| account_id | INT | 关联 tencent_account |
| business_type | VARCHAR(32) | cost_analysis 成本分析、cloud_product 云产品、balance 余额；服务端注册业务码 |
| is_enabled | TINYINT UNSIGNED | 该账号该业务的独立开关 |
| frequency / run_time / timezone | VARCHAR(16) / TIME / VARCHAR(64) | daily / weekly / monthly；执行时刻；Asia/Shanghai |
| day_of_week / day_of_month | 可空 TINYINT UNSIGNED | 周几 1–7 或每月几号 1–31；daily 两者为空，weekly 仅周字段有值，monthly 仅月字段有值 |
| next_run_at | 可空 DATETIME | 该配置下次 UTC 应执行时间 |
| settings_json | JSON | 各业务经校验的专用参数，不放凭据和业务结果 |
| state_json | JSON | 各业务独立的同步进度和覆盖状态，不存费用、余额、产品清单等结果 |
| last_success_at | 可空 DATETIME | 该账号该业务最近成功时间 |
| active_job_id | 可空 INT | 当前执行任务；原子领取以保证同配置单任务执行 |
| lease_owner / lease_until / lease_generation | 可空 VARCHAR(191) / DATETIME / INT | 配置级租约及防旧执行者覆盖的隔离代数，不是业务数据版本 |

唯一键 `(account_id, business_type)`；索引 `(is_enabled, next_run_at)`。当前每个账号的每类业务只有一套配置；不同账号或不同业务独立调度。账号和业务绑定不可编辑，配置停用后保留其历史任务和业务数据，避免悬空关联。

成本的周模式固定周日（7）、月模式固定 3 日；这一约束由成本处理器校验，不硬编码为余额、云产品的费用日期规则。成本 `settings_json` 固定费用账单 / 总费用 / 产品全量口径和核验后的币种；不得用任意筛选结果覆盖全产品费用。成本 `state_json` 含 `history_start`、`backfill_target`、`covered_until`、`month_covered_until`、`backfill_status`、缺失区间，按日期严格校验，事务更新；存在早期缺口不跨越推进。

JSON 仅为内部存储：每个已接入业务须有明确的 Pydantic 参数和状态模型，未知业务码拒绝启用。前端提供中文结构化表单，不要求用户编辑 JSON。余额没有成本账期，不套用“截至昨日”的费用范围；云产品也不套用费用历史回溯。两者具体数据含义和参数待正式接入时确认。

账号总开关和业务开关都启用才可领取任务。配置开关/账号停用与提交按统一锁顺序协调，提交前复核开关；已停用则不再提交在途新结果。调度配置更新只影响后续生成任务，已生成任务的账号、业务和范围保持固定。

### tencent_sync_job：通用同步执行任务

| 核心字段 | 拟定类型 | 用途 |
| --- | --- | --- |
| config_id / parent_job_id | INT / 可空 INT | 关联同步配置及批次父任务；账号和业务从不可变配置绑定取得 |
| job_type / trigger_type | VARCHAR(24) | backfill / incremental / refresh；定时或手动，能力由对应业务处理器校验 |
| scope_json | JSON | 入队时固定的执行范围及有效业务参数；成本含起止日期和 day / month，余额不强制账期 |
| idempotency_key | VARCHAR(191) | 同一调度事件或提交的重试复用；主动重拉创建新任务 |
| status / attempt_count | VARCHAR(24) / INT UNSIGNED | 待执行、运行、待重试、成功或失败及次数 |
| scheduled_at / retry_at | DATETIME / 可空 DATETIME | 应执行和重试时刻 |
| lease_generation | 可空 INT | 领取时取得的配置租约代数，提交时与 config 比对 |
| started_at / finished_at | 可空 DATETIME | 开始及结束时刻 |
| row_count / request_ids_json | INT UNSIGNED / JSON | 本次结果行数及分页请求标识，不保存费用、余额或产品结果副本 |
| error_summary | 可空 VARCHAR(1000) | 脱敏错误摘要，不保存密钥、原始响应及整批账单 |

唯一键 `(config_id, idempotency_key)`；索引 `(status, retry_at)`、`(config_id, scheduled_at)`。每条同步配置同一时刻只执行一个任务，不用“整个账号只能一个任务”的锁；A 的成本与余额可以独立执行，B 的余额也独立执行。并发仍须遵守各接口及账号级限流。

领取任务须原子设置 config 的 active_job_id 和租约，任务记录取得的代数。提交时锁定配置和任务，核验任务 ID、租约所有者、未过期、代数和绑定；旧任务不能在新任务接管后提交。业务处理器须验证任务范围的类型、口径以及结果账号与配置一致，不能把 scope_json 当作任意 API 调用。任务结果与该配置的状态成功更新在同一事务完成。不同业务的失败、重试和进度互不覆盖；共用凭据失效可影响实际调用，但不混写任务状态。

注册表把 business_type 映射到受控处理器，负责参数校验、范围计算、采集、校验及结果写入；通用调度器仅负责领取、租约、重试和任务状态。余额、云产品未接入处理器前，预留码不代表可以执行。

### 账号与配置示例

`tencent_account` 只有 A、B 两条账号记录。下列为 `tencent_sync_config` 的四条示意配置，未创建实际任务：

| 配置 ID | account_id / 账号 | business_type / 业务 | frequency | 执行日 |
| --- | --- | --- | --- | --- |
| 101 | 1 / A | cost_analysis / 成本分析 | monthly | 每月 3 日 |
| 102 | 1 / A | cloud_product / 云产品 | weekly | 每周日（示例） |
| 103 | 1 / A | balance / 余额 | daily | 每天 |
| 104 | 2 / B | balance / 余额 | daily | 每天 |

任务通过 config_id=101/102/103/104 分别追踪；A 停用余额只改变 103，A 成本失败只重试 101 的任务，B 余额成功只更新 104 的状态。每条配置可独立设置执行时刻、查看最近成功时间及下次执行时间。B 没有成本配置也可接入余额。

### tencent_cost_period：唯一业务账期

| 核心字段 | 拟定类型 | 用途 |
| --- | --- | --- |
| account_id | INT | 关联通用 tencent_account，所属腾讯云账号 |
| grain | VARCHAR(8) | month：完整自然月；day：完整自然日 |
| period_start / period_end | DATE | 半开区间；11 月为 `[2026-11-01,2026-12-01)` |
| currency / source_kind | CHAR(3) / VARCHAR(24) | 币种及 api_month / api_day / historical_import 来源 |
| total_amount | DECIMAL(24,8) | 与源总计校验一致的当前产品合计，可为负数 |
| item_count | INT UNSIGNED | 当前产品行数，零费用期间允许为 0 |
| last_job_id / synced_at | INT / DATETIME | 关联通用 tencent_sync_job 及 UTC 同步时间；该任务必须属于同账号的 cost_analysis 配置 |

唯一键 `(account_id, grain, period_start)`；范围查询索引 `(account_id, period_start)`。期间 ID 是稳定业务容器 ID，重复拉取同一日/月复用它，不因重拉插入新期间。只有完整成功期间落表；失败记录在 tencent_sync_job，缺口记录在对应成本配置的 state_json。未成功日期没有期间记录，成功零费用有总额为零的期间记录。不同账号的成本分别存储、筛选和对账。

### tencent_cost_item：期间内的当前产品金额

| 核心字段 | 拟定类型 | 用途 |
| --- | --- | --- |
| period_id | INT | 所属期间 |
| row_key | VARCHAR(191) | 本次完整响应归一化后的产品行标识，仅在期间内使用 |
| product_code | 可空 VARCHAR(191) | 官方字典可靠匹配后填写，不自行编造 |
| product_name / mapping_status | VARCHAR(255) / VARCHAR(24) | 原始名称及 mapped / unmapped / ambiguous 状态 |
| amount | DECIMAL(24,8) | 该期间该产品的当前总费用，有符号精确小数 |

唯一键 `(period_id, row_key)`；可按查询计划增加 `(period_id, product_code)` 索引。完整覆盖时删除全部旧产品行并重插，不用行号或中文名跨次匹配。产品码可靠时用于跨月展示，未映射和同名歧义行分别显示，不丢弃或静默合并。

精度须以真实响应验证，超精度报错，不静默截断；Python 使用 Decimal，展示才保留两位。币种不同禁止合计。产品行的日期、币种和同步任务从期间继承。

## 3. 完整期间事务覆盖

以重拉 11 月为例：

1. 固定账号、口径和 `[11-01,12-01)`，在事务外获取所有分页、字典及源总计，放入本次内存工作集。
2. 校验无重复页、漏页、提前空页和条数变动，金额可解析，产品合计与源总计一致。无法确定完整时失败退出，不动费用表。
3. 开启短事务，按统一锁顺序复核账号启用状态、锁定该账号的成本同步配置和任务，检查业务、账号、租约、当前任务及代数一致；只读核对即将替换的期间及行数。账号启用检查可用共享行锁，避免将不同业务串行化。
4. 存在 11 月月期间则复用 ID，删除其全部旧产品行，插入全部新产品行，更新总额、产品数和同步时间。若原来是日存储，在同一事务删除本月全部日产品行和日期间，写入唯一完整月数据。
5. 在该事务更新通用任务成功、对应成本配置的覆盖边界和缺口，一起提交。任何一步失败则回滚，原费用不变；失败状态另行记录。不修改余额或云产品配置的状态。

正常流程不保存旧费用副本，不长期落地原始账单响应；内存工作集不供看板读取。必要的数据库备份属于部署恢复手段，不是费用版本功能。

只有源端明确已准备、分页确认完整、源总计为零且允许空产品集时，才用零覆盖旧非零金额。空页、无权限、未准备、解析失败不能触发清空。

看板一次响应中的总额、产品表和日期覆盖状态在同一个一致性读事务中查询；提交前看到原完整数据，提交后看到新完整数据，不看到删除和插入之间的中间态。

## 4. 日、周、月只存一份

| 场景 | 存储与查询 |
| --- | --- |
| 月同步 | 每月一个 period，产品各一行；每月 3 日覆盖上个完整自然月 |
| 日/周同步 | 完整自然日各存一个 period；看板查询时按月求和，不另存月聚合金额 |
| 日/周切到月 | 完整月拉取校验通过后，事务内删除该月日数据并写入月数据 |
| 月切到日/周 | 保留历史完整月，已覆盖日期不再写日记录；未覆盖日期继续按日采集 |
| 日范围补拉遇到月记录 | 明确展示按整月补拉的实际范围，重取并覆盖整月，不叠加几天金额 |

同一账号同一自然月只允许月记录或日记录二选一。唯一键不能防止日/月相交，应用须在该账号的成本配置锁内检查重叠期间。只有月汇总的历史不能平均拆为虚构日数据。日模式当前月覆盖不全时，显示累计截止日和缺口，不显示为完整月。

## 5. 虚拟存储与覆盖示例

假设账号 1「A」、成本配置 101、每月 3 日 13:30（建议时刻）、费用账单 / 总费用 / 产品 / CNY。该账号还可有独立余额和云产品配置，不影响下面费用数据。最早账期假设为 9 月仅为举例，不限制真实回溯范围。

`tencent_cost_period` 的 11 月唯一记录：

| id | account_id | grain | period_start | period_end | total_amount | item_count |
| --- | --- | --- | --- | --- | ---: | ---: |
| 11 | 1 | month | 2026-11-01 | 2026-12-01 | 12700.00000000 | 5 |

`tencent_cost_item`：

| period_id | row_key | product_name | amount |
| --- | --- | --- | ---: |
| 11 | row_1 | 云服务器 CVM | 6200.00000000 |
| 11 | row_2 | 云数据库 MySQL | 3800.00000000 |
| 11 | row_3 | 对象存储 COS | 1300.00000000 |
| 11 | row_4 | 内容分发网络 CDN | 1150.00000000 |
| 11 | row_5 | 负载均衡 CLB | 250.00000000 |

模拟 12 月 5 日重拉：腾讯云把 CDN 更正为 950.00 元，不再返回 CLB，源总计为 12250.00 元。覆盖后仍为 period 11，总额更新为 `12250.00000000`、产品数 4，原 5 行完整替换为：

| period_id | row_key | product_name | amount |
| --- | --- | --- | ---: |
| 11 | row_1 | 云服务器 CVM | 6200.00000000 |
| 11 | row_2 | 云数据库 MySQL | 3800.00000000 |

| 11 | row_4 | 内容分发网络 CDN | 950.00000000 |

数据库没有旧 CDN 金额，没有旧 CLB 行，没有另一份 11 月账单。再次同步同样结果仍是 4 行、12250 元。上述前后表仅为解释，业务库不同时保存两套。

## 6. 看板展示

覆盖后的虚拟数据：

| 产品 | 2026-09 | 2026-10 | 2026-11 |
| --- | ---: | ---: | ---: |
| 云服务器 CVM | 5000.00 | 5500.00 | 6200.00 |
| 云数据库 MySQL | 3200.00 | 3500.00 | 3800.00 |
| 对象存储 COS | 1000.00 | 1100.00 | 1300.00 |
| 内容分发网络 CDN | 1100.00 | 900.00 | 950.00 |
| 负载均衡 CLB | 200.00 | 200.00 | — |
| **总费用（元）** | **10500.00** | **11200.00** | **12250.00** |

11 月环比 +9.38%，三个月合计 33950.00 元。CLB 的 11 月显示“—（源端无该产品记录）”，不沿用 250 元；真实返回零金额的产品显示 0.00。无源行不贡献总额，期间总计仍须与源总计一致。12 月在月模式显示“待 2027-01-03 同步”，不是 0 元。

图表与表格读取同一套当前费用，不提供版本选择。表格及导出保留全部产品，图表可 Top10 加其他。无法可靠映射的源产品行单列展示；日聚合也不能仅凭同名推定为同一产品。

管理页分为“腾讯云账号”和“业务同步配置”：账号页维护身份和凭据引用，配置页按账号、业务、频率、启用状态、最近成功、下次执行逐行展示。成本的日期说明只出现在成本配置中；余额展示查询成功时刻，不显示“账单已覆盖至昨日”。余额及云产品结果由未来各自业务表保存，不塞入成本期间/产品表或通用配置 JSON。

“完全覆盖腾讯云”在一期指已确认的费用账单 / 总费用 / 产品口径下，全分页、全产品、全部成功回溯期间的当前金额，不代表所有财务功能、资源明细、地域/项目维度或摊销账单。历史调账需重新采集对应账期；提供指定账期重拉和全历史重新覆盖能力，可取回历史范围以真实接口结果为准，不擅自扩大每次月同步范围。

## 7. 验证与实施边界

实施前核实目标 MySQL 版本、schema、字符集及会话配置，提供迁移预检和恢复说明；真实写入另按授权执行。联调验证 API 全分页、维度、单位、精度、历史边界及对账。本次只修订设计。

实施验收包括：A 的三业务、B 的余额配置可独立保存；重复账号＋业务被拒绝；业务停用不影响同账号其他业务；账号总停用阻止所属业务领取和在途提交；成本失败不推进余额或 B 的进度；同配置任务互斥、跨配置允许并行且正确限流；不同账号不串数据；重复同步一份费用；消失产品无残留；有效零账单可清除旧非零金额；空页或失败不误清空；事务失败完整回滚；日/月无重复期间；过期任务不能写入；查询无中间态；不误删其他月份；缺口与未同步状态可见。余额、云产品处理器未接入前仅验证配置模型和调度契约，不宣称真实业务同步通过。使用真实隔离 MySQL 验证，不用文档示例代替。
