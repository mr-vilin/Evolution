# 腾讯云 T07 日周同步与日月切换

日期：2026-11-17（Asia/Shanghai）。范围：Issue #22，基于集成 `f7bd18c8eeaef87352c6809efa40de51075796ab` 的既有手动月、月批次、恢复及看板能力。本文记录本地实现和隔离验证，不代表真实腾讯云账单、CAM、业务数据库或运行部署验收。

## 期间、调度和契约

- `daily` 每日、`weekly` 固定周日，按配置的北京时间时分执行；只创建最近一个已到计划点，重复 tick、并发节点与普通配置编辑使用同一日历事件身份。`monthly` 保留每月 3 日及原月度事件身份。
- 受理事务冻结实际自然日及 `Asia/Shanghai` 半开边界。日/周批次复核当月截至计划点昨日的每一天及整个上月；当月优先，随后上月，再有限加入更早缺口。排队、跨午夜重试和切换频率均不扩大已经冻结的范围。运行、审计、租约和执行时间继续使用 UTC。
- 原始期间统一通过 `period_snapshot(..., granularity, period_key)` 建立，新增快照契约为 `tencent-cost-period-v2`。`collect_period` 是实际采集器；`collect_month` 是兼容旧 Python 入口的别名。已受理的 `tencent-cost-month-v1` 只允许完整月，回执保留原契约身份。
- `period_key` 对月为 `YYYY-MM`，对日为 `YYYY-MM-DD`；原有 `month` 表示归属月。父批次仅汇总实际日/月子期间，不领取租约、不创建执行尝试；子尝试继续经过当前初始化、管理员或可信系统身份、账号/凭据修订、成本开关、owner/代数和截止时间门禁。
- 普通频率修改只影响新轮次；旧月系统身份及已冻结日快照均保留原范围，在当前安全门禁下继续运行。成本开关与实时余额能力仍相互独立。

## 日月互斥和失败保留

受理和发布共用配置锁。新受理的单日若命中已保存完整月，先规范化为完整月，再冻结快照；同一批次规范化后去重。先前已经冻结的单日若执行时才出现完整月，返回 `TENCENT_COST_PERIOD_OVERLAP`，不能在执行中自行扩大范围。

日转月成功时，同一发布事务删除该月的全部日费用及产品、写入完整月及其全量产品并提交回执。任何采集、资格或发布失败都回滚并保留原日结果。月转日保留完整月，之后涉及它的重拉仍按完整月处理，不分摊或伪造日金额。期间唯一键不含组织 epoch；已成功费用在组织重来后仍有效，在途任务仍严格受原 epoch 栅栏约束。

所有日分页沿用既有总条数、重复页、精确十进制金额、产品及总计、时间归属和首次页重读检查。独立配置仍可并发，共享每动作 20 次/秒出站治理与冻结预算。迟到费用通过规定近期复核更新该日全量产品，消失产品会被删除。

## 零日与旧缺口边界

目前没有已核实的官方独立日级 Ready / 零值证据。空日或产品全部显式为零，统一返回 `TENCENT_COST_ZERO_UNCONFIRMED`，保留旧费用并按冻结次数/时间预算有限重试；不会调用整月产品汇总充当日零值证明。存在正负产品且净额为零时保留全部产品并可成功。页面展示此限制，不把未确认日当作已覆盖零费用。

更早缺口按固定配置日期锚点和已有失败范围有限补入，每批最多增加 31 个旧日/月期间，并受总队列上限限制。只计入同一 epoch、凭据修订、已结束自动父批次的失败，每个实际范围每个父批次计一次；手动失败和仍未结束批次不消耗自动次数。满 3 次后标明自动预算耗尽，近期复核仍可继续。日/周频率共享实际范围的次数；完整月预算保留月范围身份。

日期锚点不代表历史起点；本任务不将空结果、6 个月日窗或 12 个月月窗解释为账号全历史完成。历史来源窗口、持久化探测游标、已有历史缺口优先级由 T08 扩展。

## 查询、导出和界面

- 看板和 CSV 在同一一致读事务中直接聚合原始日费用，不另存一份月费用。可靠 `BusinessCode` 可跨日聚合，未映射或歧义行保持期间内独立身份；日月重叠明确拒绝，禁止双重求和。
- 只有实际覆盖完整自然月所有日期且口径一致时，日累计才标为完整月；当前月/局部日期显示已知累计、来源粒度、已采集日期、最大实际日期及缺失日期，完整范围金额和不可比同比/环比保持空值。某日成功不能遮蔽其他日的较新失败。
- 旧 `GET cost-periods/{month}` 对已有月行保留原外壳；只有日行时复用看板的真实月聚合，并返回 `granularity=day`、真实日期/缺口和覆盖状态，产品数组为查询时聚合结果，`id=daily:YYYY-MM` 为只读聚合身份。`GET cost-periods/YYYY-MM-DD` 精确返回原始单日。聚合不产生持久化记录。
- 中文结构化界面支持每日/周日配置、下次计划、实际最近成功期间、立即批次与真实子期间失败/重跑；月详情累计不误标完整覆盖。完整月手动采集继续遵守每月 3 日开放边界。

## 数据库迁移与恢复

唯一 head：`0019_tencent_daily`，下接 `0018_tencent_monthly`。新增日期锚点、真实粒度和期间键；旧月键从原 `month` 原值回填，保留主键、金额、产品、回执。唯一键改为 `(account_id, period_key, currency)`，新增归属月索引。新增字段及相关既有描述均有中文字段备注，ORM、迁移和 `CURRENT_SCHEMA_HEAD` 同步。

业务库执行前另行授权，核验目标 MySQL 8.4、实际迁移、表类型/字符集/排序规则、稳定 ID 二进制比较、重复范围及孤儿产品；确认所有云 worker 已静默，包含过期但未释放 owner、active_job_id 和 running/retry 状态；保存结构/数据备份与恢复点。迁移只改本任务结构，不运行成本采集。执行后核验唯一 head、所有旧月键回填、金额/产品/回执数量与值、索引和中文备注，并运行 schema_check。

MySQL DDL 非事务，失败不得假定自动回滚，应停止工作器、核对实际已执行步骤和备份后恢复或受控续行。存在日费用、日/周配置、已保存日期锚点、任何日快照，或旧应用无法执行的活动 period-v2 快照时，降级在任何 DDL 前拒绝，保留证据；跨过0018且有父批次时同样提前拒绝，避免先降0019再卡在0018。仅无上述新状态证据且允许的测试/备份目标可演练0018降升；运行回退优先回退应用并保留财务数据，不删除日记录换取降级成功。

## T08 可复用接点

`cost_scheduler.accept_batch` 是持有当前账号/配置锁的真实受理入口；`period_snapshot` 建立冻结日/月范围，`cost_worker` 是唯一实际采集、发布及恢复路径。T08 应在受理阶段组合有界历史期间并规范化已有完整月，保留当前近期优先、实际期间身份、旧范围次数与原子发布；查询继续使用 `read_dashboard(db, account_id, params, *, now=None)`。不得把父批次当作一次真实尝试或为历史能力复制费用表。
